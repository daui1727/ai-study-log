## 1. MySQL과 데이터베이스

### MySQL이란?

**MySQL**은 관계형 데이터베이스 관리 시스템(RDBMS)이다.  
데이터를 여러 개의 **테이블**에 저장하고, SQL을 이용해 데이터를 조회·추가·수정·삭제할 수 있다.

- **MySQL 서버**: 데이터베이스를 실제로 관리하고 요청을 처리하는 프로그램
- **mysqld**: MySQL 서버의 실제 프로세스 이름
- **데몬(Daemon)**: 운영체제의 백그라운드에서 계속 실행되면서 특정 서비스를 제공하는 프로그램
- **MySQL Workbench**: MySQL 데이터베이스를 GUI 환경에서 관리하고 SQL을 작성할 수 있는 도구

**MySQL 8.0.17 버전과 MySQL Workbench를 설치**

## 2. 데이터베이스란?

**데이터베이스(Database)**는 여러 사람이 공유하고 사용할 목적으로 데이터를 체계적으로 저장하고 관리하는 데이터의 집합이다.

데이터베이스의 특징을 크게 보면 **공유 데이터, 통합 데이터, 저장 데이터, 운영 데이터**로 설명할 수 있다.

### DBMS란?

**DBMS(Database Management System)**는 데이터베이스를 관리하고 사용자가 데이터에 접근할 수 있도록 해주는 소프트웨어다.

예를 들어 MySQL, Oracle, PostgreSQL 등이 있다.

**사용자 → DBMS → 데이터베이스**

즉, 사용자가 직접 데이터 파일을 수정하는 것이 아니라 **DBMS를 통해 데이터베이스를 관리한다.**

---

## 3. 데이터의 종류

데이터는 구조화 정도에 따라 크게 세 가지로 나눌 수 있다.

| 종류 | 특징 | 예시 |
|---|---|---|
| **정형 데이터** | 미리 정해진 구조에 맞춰 저장 | 엑셀, 관계형 DB 테이블 |
| **반정형 데이터** | 일정한 구조나 메타데이터를 가지고 있지만 관계형 테이블처럼 엄격하지 않음 | JSON, XML, HTML |
| **비정형 데이터** | 정해진 구조가 없음 | 이미지, 영상, PDF, 문서, SNS 데이터 |

> **핵심:** 관계형 데이터베이스는 대표적인 **정형 데이터**를 다루는 시스템이다.

# 4. 관계형 데이터베이스(RDBMS)

데이터를 저장하고 조회하는 작업은 매우 중요하기 때문에, 관계형 데이터베이스의 기본 구조를 이해하는 것이 필요하다.

관계형 데이터베이스는 데이터를 **테이블(Table)** 형태로 저장하고, 테이블 사이의 관계를 **Primary Key(PK)**와 **Foreign Key(FK)** 등을 이용해 연결한다.

### 테이블의 기본 구성

| 용어 | 다른 표현 | 의미 |
|---|---|---|
| **Table** | Relation | 데이터를 저장하는 공간 |
| **Column** | Attribute, Field | 데이터의 속성 |
| **Row** | Tuple, Record | 하나의 데이터 정보 |
| **Relationship** | 관계 | 테이블과 테이블이 연결되는 방식 |

예를 들어 `고객` 테이블이 있다면 다음과 같이 생각할 수 있다.

| 고객번호 | 담당자명 | 고객회사명 | 마일리지 |
|---|---|---|---:|
| 10001 | 김철수 | ABC회사 | 50000 |
| 10002 | 이영희 | XYZ회사 | 120000 |

여기서 `고객번호`, `담당자명`, `고객회사명`, `마일리지`는 **Column**이고, 각각의 고객 데이터 한 줄은 **Row**다.

---

## 5. Primary Key와 Foreign Key

### Primary Key(PK)

**Primary Key(기본키)**는 테이블의 각 행을 구별하기 위한 식별자다.

예를 들어 고객번호가 중복되지 않는다면 `고객번호`를 고객 테이블의 PK로 사용할 수 있다.

> **PK의 핵심:** "이 데이터가 누구인지 구별하기 위한 값"

### Foreign Key(FK)

**Foreign Key(외래키)**는 다른 테이블의 PK 등을 참조하여 테이블과 테이블을 연결하기 위한 값이다.

예를 들어 `주문` 테이블에 `고객번호`가 있다면, 이 값으로 `고객` 테이블의 특정 고객과 주문을 연결할 수 있다.

> **PK = 나를 식별하는 키**  
> **FK = 다른 테이블과 연결하기 위한 키**

# 6. ERD와 데이터 모델링

### ERD(Entity-Relationship Diagram)

**ERD**는 데이터베이스의 테이블과 테이블 사이의 관계를 그림으로 표현한 것이다.

ERD를 이용하면 데이터베이스를 만들기 전에 **어떤 테이블이 존재하고, 서로 어떻게 연결되는지**를 한눈에 파악할 수 있다.

### Crow's Foot Notation

ERD에서는 **까마귀발 표기법(Crow's Foot Notation)**을 사용해 관계의 개수를 표현하기도 한다.

- `|` → 1개
- `O` → 0개 또는 1개
- `<` 모양 → 여러 개

예를 들어 **주문 하나에 여러 개의 주문 상세 정보가 존재할 수 있다.**

또한 **부서 하나에 사원이 0명 이상 존재할 수 있다.**

### 식별 관계와 비식별 관계

- **실선 = 식별 관계**: 자식 테이블의 PK에 부모 테이블의 PK가 포함되는 관계
- **점선 = 비식별 관계**: 부모의 PK가 자식 테이블의 PK에 포함되지 않고 FK 등의 형태로 연결되는 관계

> **데이터 모델링**은 데이터베이스를 만들기 전에  
> **"무슨 데이터를, 어떤 구조로, 어떤 관계로 저장할 것인가?"**를 설계하는 과정이다.

# 7. SQL이란?

**SQL(Structured Query Language)**은 관계형 데이터베이스의 데이터를 관리하고 조작하기 위한 표준화된 언어다.

SQL의 중요한 특징 중 하나는 **절차적으로 하나씩 처리하기보다 데이터를 집합(Set) 단위로 다룬다는 것**이다.

예를 들어 특정 고객 한 명만 조회할 수도 있지만, 조건에 맞는 고객 전체를 한 번에 조회할 수도 있다.

---

## 8. SQL의 주요 명령어 분류

### DDL - 데이터 정의어

데이터베이스 객체의 구조를 정의하거나 변경한다.

`CREATE` → 객체 생성  
`ALTER` → 객체 구조 변경  
`DROP` → 객체 삭제  
`TRUNCATE` → 테이블의 모든 데이터 삭제

### DML - 데이터 조작어

테이블의 데이터를 조회하거나 추가·수정·삭제한다.

`SELECT` → 데이터 조회  

`INSERT` → 데이터 추가  
`UPDATE` → 데이터 수정  
`DELETE` → 데이터 삭제

### DCL - 데이터 제어어

데이터베이스에 대한 권한을 관리한다.

`GRANT` → 권한 부여  
`REVOKE` → 권한 회수

### TCL - 트랜잭션 제어어

트랜잭션의 변경사항을 확정하거나 되돌린다.

`COMMIT` → 변경사항 확정  
`ROLLBACK` → 변경사항 되돌리기

> **처음에는 SELECT를 확실하게 익히는 것이 중요하다.**  
> 이후 WHERE → ORDER BY → GROUP BY → HAVING → JOIN → 서브쿼리 순서로 확장해 나간다.
