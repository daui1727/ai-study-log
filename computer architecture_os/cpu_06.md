# 06-1. RAM의 특성과 종류

> **주기억장치의 종류에는 크게 RAM과 ROM이 있다.**

## 📌 학습 목표

* RAM의 특징인 **휘발성(Volatile)**을 이해한다.
* RAM이 필요한 이유를 이해한다.
* **DRAM, SRAM, SDRAM, DDR SDRAM**의 특징과 차이를 이해한다.

---

# 1. RAM의 기본적인 특징과 존재 이유는 무엇일까?

CPU는 프로그램을 실행할 때 필요한 데이터를 **메모리(RAM)**에서 가져온다.

반면 실행이 끝난 데이터나 프로그램을 장기간 보존해야 하는 경우에는 **보조기억장치(HDD, SSD 등)**에 저장한다.

```
보조기억장치
(HDD / SSD)
      │
      │ 필요한 프로그램과 데이터 가져오기
      ↓
메모리
(RAM)
      │
      │ CPU가 사용할 데이터 전달
      ↓
CPU
```

---

## 🔌 RAM은 휘발성 저장 장치

RAM은 **휘발성 저장 장치(Volatile Memory)**

즉, **전원이 꺼지면 RAM에 저장되어 있던 데이터가 사라진다.**

반면 HDD나 SSD와 같은 보조기억장치는 **비휘발성 저장 장치(Non-volatile Memory)**이기 때문에 전원이 꺼져도 데이터가 유지된다.

| 구분     | RAM                    | HDD / SSD   |
| ------ | ---------------------- | ----------- |
| 종류     | 주기억장치                  | 보조기억장치      |
| 전원 OFF | 데이터 사라짐                | 데이터 유지      |
| 특징     | CPU가 실행할 프로그램과 데이터를 저장 | 데이터를 장기간 보존 |
| 휘발성    | 휘발성                    | 비휘발성        |

---

## 💡 RAM의 용량이 중요한 이유

RAM의 용량이 작다면 실행할 프로그램이나 데이터를 충분히 올려놓기 어렵다.

그러면 CPU가 필요한 데이터를 보조기억장치에서 가져오는 작업이 자주 발생할 수 있다.

반대로 RAM의 용량이 충분하면 **여러 프로그램과 데이터를 RAM에 올려놓고 사용할 수 있기 때문에 여러 프로그램을 동시에 실행하는 데 유리하다.**

> **RAM이 크다고 CPU 자체의 연산 속도가 빨라지는 것은 아니지만, 여러 프로그램과 데이터를 메모리에 충분히 유지할 수 있어 메모리 부족으로 인한 성능 저하를 줄이는 데 도움이 된다.**

---

# 2. RAM의 대표적인 종류

RAM에는 여러 종류가 있으며 대표적으로 다음과 같은 것들이 있다.

* DRAM
* SRAM
* SDRAM
* DDR SDRAM

---

# 3. DRAM (Dynamic RAM)

**DRAM = Dynamic Random Access Memory**

Dynamic은 **동적**이라는 뜻

DRAM은 저장된 데이터가 시간이 지나면서 유지되기 어려워지기 때문에 **주기적으로 데이터를 다시 활성화하는 리프레시(Refresh)**가 필요하다.

```
DRAM

데이터 저장
   ↓
시간이 지나면서 데이터 유지가 어려워짐
   ↓
Refresh
   ↓
데이터 유지
```

### DRAM의 특징

* 데이터 유지를 위해 **주기적인 리프레시가 필요하다.**
* SRAM보다 상대적으로 느리다.
* 소비 전력이 비교적 낮다.
* 가격이 비교적 저렴하다.
* 집적도가 높아 **대용량으로 만들기 유리하다.**
* 따라서 컴퓨터의 **주기억장치(RAM)**로 주로 사용된다.

### 💡 핵심

> **DRAM은 대용량의 메모리를 비교적 저렴하게 만들 수 있기 때문에 컴퓨터의 주기억장치로 널리 사용된다.**

---

# 4. SRAM (Static RAM)

**SRAM = Static Random Access Memory**

Static은 **정적**이라는 뜻

SRAM은 DRAM과 달리 저장된 데이터를 유지하기 위해 **주기적인 리프레시가 필요하지 않다.**

### SRAM의 특징

* 리프레시가 필요하지 않다.
* DRAM보다 빠르다.
* 집적도가 낮다.
* 소비 전력이 상대적으로 크다.
* 가격이 비싸다.
* 대용량으로 만들기 어렵다.
* 따라서 **캐시 메모리** 등에 주로 사용된다.

### DRAM과 비교

| 구분    | DRAM     | SRAM     |
| ----- | -------- | -------- |
| 리프레시  | 필요       | 불필요      |
| 속도    | 상대적으로 느림 | 상대적으로 빠름 |
| 집적도   | 높음       | 낮음       |
| 용량    | 대용량에 유리  | 대용량에 불리  |
| 가격    | 저렴       | 비쌈       |
| 주요 용도 | 주기억장치    | 캐시 메모리   |

### 💡 쉽게 기억하기

> **DRAM = 크고 저렴하게 만들기 유리 → RAM(주기억장치)**
> **SRAM = 빠르지만 비싸고 작음 → 캐시 메모리**

---

# 5. SDRAM (Synchronous DRAM)

**SDRAM = Synchronous Dynamic RAM**

SDRAM은 **클럭 신호와 동기화되어 동작하는 DRAM**

즉, CPU와 메모리 시스템이 사용하는 클럭 신호의 타이밍에 맞춰 데이터를 처리한다.

> **SDRAM은 클럭 신호와 동기화되어 동작하도록 발전한 DRAM**

---

# 6. DDR SDRAM

**DDR SDRAM = Double Data Rate SDRAM**

DDR은 **Double Data Rate**의 약자

SDRAM은 클럭 신호와 동기화되어 동작하는데, DDR SDRAM은 **한 클럭 주기에서 데이터를 전송하는 횟수를 늘려 대역폭을 높인 메모리**

### 💡 대역폭(Bandwidth)이란?

대역폭은 쉽게 말하면

> **단위 시간당 전송할 수 있는 데이터의 양**

DDR SDRAM은 데이터 전송을 한 클럭 주기에서 두 번 수행할 수 있도록 하여 SDR SDRAM보다 높은 대역폭을 제공한다.

---

## DDR의 발전

DDR 이후에도 DDR2, DDR3, DDR4, DDR5 등으로 계속 발전해왔다.

세대가 올라갈수록 일반적으로 더 높은 데이터 전송 속도와 대역폭을 제공한다.

```
SDRAM
  ↓
DDR
  ↓
DDR2
  ↓
DDR3
  ↓
DDR4
  ↓
DDR5
```

> **DDR 세대가 올라간다고 단순히 대역폭이 매번 정확히 2배가 되는 것은 아니다.**
>
> 각 세대는 더 높은 데이터 전송 속도와 다양한 기술적 개선을 통해 성능을 높여왔다.

---

# 7. RAM 종류 한눈에 정리

```
RAM
│
├── DRAM
│    └── 대용량 / 저렴 / 주기억장치
│
├── SRAM
│    └── 빠름 / 비쌈 / 캐시 메모리
│
├── SDRAM
│    └── 클럭과 동기화된 DRAM
│
└── DDR SDRAM
     └── 데이터 전송량을 높인 SDRAM 계열
```

### ⭐ 핵심 정리

> **DRAM은 대용량 주기억장치에 적합하고, SRAM은 빠르기 때문에 캐시 메모리에 적합하다. SDRAM은 클럭과 동기화된 DRAM이며, DDR SDRAM은 데이터 전송량을 높인 발전된 SDRAM 계열**

# 06-2. 메모리의 주소 공간

## 📌 학습 목표

* **물리 주소와 논리 주소**의 차이를 이해한다.
* **MMU(Memory Management Unit)**의 역할을 이해한다.
* 베이스 레지스터와 한계 레지스터를 이용한 메모리 보호 방식을 이해한다.

---

# 1. CPU와 메모리가 사용하는 주소가 서로 다른 이유는?

CPU가 메모리에 있는 데이터를 사용하려면 데이터가 어디에 있는지 알아야 한다.

이를 위해 **주소(Address)**를 사용한다.

그런데 CPU가 사용하는 주소와 실제 메모리 하드웨어가 사용하는 주소는 다를 수 있다.

대표적으로 다음 두 가지 주소가 있다.

* **논리 주소(Logical Address)**
* **물리 주소(Physical Address)**

---

# 2. 물리 주소(Physical Address)

물리 주소는

> **메모리 하드웨어가 실제로 사용하는 주소**

즉, 실제 RAM의 어느 위치에 데이터가 저장되어 있는지를 나타내는 **실제 메모리상의 주소**

```
RAM

0번지
1번지
2번지
3번지
...
```

CPU가 직접 이 실제 주소를 사용하는 것이 아니라, 프로그램은 일반적으로 논리 주소를 사용한다.

---

# 3. 논리 주소(Logical Address)

논리 주소는

> **CPU와 실행 중인 프로그램이 사용하는 주소**

프로그램마다 자신만의 주소 공간을 사용하는 것처럼 보이게 만들 수 있으며, 프로그램 입장에서는 보통 자신의 시작 위치를 **0번지**로 생각한다.

즉, 논리 주소는 실제 RAM의 절대적인 위치라기보다는

> **프로그램의 시작 위치를 기준으로 한 상대적인 주소**

라고 이해하면 쉽다.

예를 들어 프로그램에서

```
논리 주소 0
논리 주소 1
논리 주소 2
논리 주소 3
...
```

를 사용한다고 해보자.

이 프로그램이 실제 RAM의 1000번지부터 저장되어 있다면:

```
논리 주소 0 → 물리 주소 1000
논리 주소 1 → 물리 주소 1001
논리 주소 2 → 물리 주소 1002
```

와 같이 대응시킬 수 있다.

---

# 4. 논리 주소를 물리 주소로 변환하는 방법

논리 주소를 실제 메모리의 물리 주소로 변환하는 역할을 하는 하드웨어가

**MMU(Memory Management Unit)**

> **MMU는 CPU가 사용하는 논리 주소를 물리 주소로 변환해준다.**

```
CPU
 │
 │ 논리 주소
 ↓
MMU
 │
 │ 물리 주소
 ↓
RAM
```

---

# 5. 베이스 레지스터(Base Register)

논리 주소를 물리 주소로 변환할 때 **베이스 레지스터**를 사용할 수 있다.

베이스 레지스터에는

> **프로그램의 시작 물리 주소**

가 저장된다.

논리 주소가 프로그램 시작 위치로부터 얼마나 떨어져 있는지를 나타내는 값이라면 다음과 같이 계산할 수 있다.

```
물리 주소 = 논리 주소 + 베이스 레지스터 값
```

예를 들어,

```
베이스 레지스터 = 1000
논리 주소 = 50
```

이라면,

```
물리 주소
= 50 + 1000
= 1050
```

이 된다.

### 💡 쉽게 생각하기

```
실제 프로그램 시작 위치
        ↓
      1000번지
        │
        ├── 논리 주소 0 → 물리 주소 1000
        ├── 논리 주소 1 → 물리 주소 1001
        ├── 논리 주소 2 → 물리 주소 1002
        └── 논리 주소 50 → 물리 주소 1050
```

즉,

> **논리 주소는 프로그램의 시작점으로부터 얼마나 떨어져 있는지를 나타내고, 베이스 레지스터는 실제 메모리에서 프로그램이 시작하는 위치를 나타낸다.**

---

# 6. 다른 프로그램의 영역을 침범하지 않으려면?

논리 주소를 물리 주소로 변환할 수 있다면 한 가지 문제가 생길 수 있다.

> **프로그램이 자신에게 할당된 메모리 영역을 넘어 다른 프로그램의 메모리에 접근하면 어떻게 할까?**

이를 막기 위해 **한계 레지스터(Limit Register)**를 사용할 수 있다.

---

# 7. 한계 레지스터(Limit Register)

한계 레지스터에는

> **프로그램이 사용할 수 있는 논리 주소의 최대 범위**

가 저장된다.

CPU가 메모리에 접근하기 전에 논리 주소가 허용된 범위를 벗어나는지 확인한다.

```
CPU가 접근하려는 논리 주소
          ↓
한계 레지스터와 비교
          ↓
┌──────────────────────┐
│ 범위 안       범위 밖 │
│   ↓             ↓     │
│ 정상 접근      차단    │
└──────────────────────┘
```

범위를 벗어난 주소에 접근하려고 하면 **인터럽트(트랩)**가 발생하고 접근이 차단된다.

---

# 8. 베이스 레지스터 + 한계 레지스터

두 레지스터를 함께 사용하면 프로그램의 메모리 영역을 보호할 수 있다.

```
CPU
 │
 │ 논리 주소
 ↓
┌─────────────────┐
│ 한계 레지스터 검사 │
└─────────────────┘
 │
 ├── 범위 초과 → 트랩 발생 → 접근 차단
 │
 └── 범위 내
        ↓
       MMU
        ↓
물리 주소 = 논리 주소 + 베이스 레지스터
        ↓
       RAM
```

### ⭐ 핵심

> **한계 레지스터는 접근 가능한 범위를 검사하고, 베이스 레지스터는 실제 메모리에서 프로그램이 시작하는 위치를 제공한다.**

이를 통해 프로그램이 다른 프로그램의 메모리 영역을 함부로 침범하는 것을 방지할 수 있다.

---

# 9. 논리 주소 vs 물리 주소

| 구분        | 논리 주소             | 물리 주소         |
| --------- | ----------------- | ------------- |
| 사용하는 주체   | CPU / 프로그램        | 메모리 하드웨어      |
| 의미        | 프로그램 기준의 상대적인 주소  | 실제 RAM의 주소    |
| 실제 RAM 위치 | 직접 나타내지 않음        | 실제 위치를 나타냄    |
| 변환        | MMU를 통해 물리 주소로 변환 | 실제 메모리 접근에 사용 |

# 06-3. 캐시 메모리

## 📌 학습 목표

* **저장 장치 계층 구조(Memory Hierarchy)**를 이해한다.
* 캐시 메모리가 필요한 이유를 이해한다.
* 캐시 히트와 캐시 미스를 이해한다.
* **참조 지역성의 원리(Locality of Reference)**를 이해한다.
* 시간 지역성과 공간 지역성의 차이를 이해한다.

---

# 1. CPU와 메모리의 속도 차이

CPU의 연산 속도는 매우 빠르다.

하지만 CPU가 메모리에 접근해서 데이터를 가져오는 속도는 CPU의 연산 속도에 비해 상대적으로 느릴 수 있다.

그렇다면 이런 문제가 생긴다.

```
CPU
 ↓
"데이터 필요!"
 ↓
RAM에 접근
 ↓
데이터 기다림...
 ↓
CPU 연산
```

CPU가 메모리에서 데이터를 가져오는 동안 기다리는 시간이 발생할 수 있다.

> **CPU가 아무리 빨라도 메모리 접근을 기다리는 시간이 길다면 CPU의 성능을 제대로 활용하기 어렵다.**

그렇다면 이 속도 차이를 어떻게 줄일 수 있을까?

---

# 2. 저장 장치 계층 구조(Memory Hierarchy)

컴퓨터의 저장 장치는 CPU와 가까울수록 일반적으로 빠르고, 멀어질수록 느려진다.

반대로

> **빠른 저장 장치는 용량이 작고 가격이 비싸며, 느린 저장 장치는 용량이 크고 가격이 저렴하다.**

대표적인 저장 장치 계층 구조는 다음과 같다.

```
          빠름 ↑
               │
          레지스터
               │
        캐시 메모리
          (SRAM)
               │
          메모리
          (DRAM)
               │
       보조기억장치
        (SSD / HDD)
               │
          느림 ↓
```

### 저장 장치 계층의 특징

위쪽으로 갈수록:

* CPU와 가까움
* 속도가 빠름
* 저장 용량이 작음
* 가격이 비쌈

아래쪽으로 갈수록:

* CPU와 멀어짐
* 속도가 느림
* 저장 용량이 큼
* 상대적으로 저렴함

---

# 3. 캐시 메모리(Cache Memory)란?

캐시 메모리는

> **CPU와 메모리(RAM) 사이의 속도 차이를 줄이기 위해 사용하는 빠른 메모리**

캐시 메모리는 일반적으로 **SRAM**을 기반으로 만들어진다.

CPU와 가까운 위치에 두어 CPU가 자주 사용하는 데이터를 빠르게 가져올 수 있도록 한다.

```
CPU
 ↓
캐시 메모리
 ↓
RAM
 ↓
SSD / HDD
```

즉,

> **CPU가 RAM까지 매번 직접 접근하는 시간을 줄이기 위한 중간 저장 공간**

이라고 생각하면 쉽다.

---

# 4. L1, L2, L3 캐시

캐시 메모리는 하나만 있는 것이 아니라 여러 계층으로 나누어 사용할 수 있다.

대표적으로

* L1 캐시
* L2 캐시
* L3 캐시

가 있다.

```
CPU
 │
 ├── L1 Cache
 │
 ├── L2 Cache
 │
 └── L3 Cache
        ↓
       RAM
```

일반적으로

> **L1 → L2 → L3 순서로 CPU에서 멀어지고, 용량은 커지며, 속도는 느려진다.**

L1 캐시는 가장 빠르고 용량이 작으며 CPU 코어와 매우 가깝다.

L2는 L1보다 크지만 조금 느리고, L3는 더 크지만 상대적으로 느리다.

멀티코어 CPU에서는 캐시가 코어별로 존재하는 경우가 있고, L3 캐시처럼 여러 코어가 공유하는 구조도 사용된다.

> **구체적인 캐시 구성은 CPU 설계에 따라 달라질 수 있다.**

---

# 5. 캐시 히트(Cache Hit)

CPU가 필요한 데이터를 캐시에서 찾았을 때를

**캐시 히트(Cache Hit)**

라고 한다.

```
CPU
 ↓
"데이터 필요"
 ↓
캐시 확인
 ↓
데이터 있음! ✅
 ↓
바로 사용
```

캐시에 필요한 데이터가 있기 때문에 RAM까지 접근할 필요가 없다.

---

# 6. 캐시 미스(Cache Miss)

반대로 CPU가 필요한 데이터를 캐시에서 찾지 못한 경우를

**캐시 미스(Cache Miss)**

라고 한다.

```
CPU
 ↓
"데이터 필요"
 ↓
캐시 확인
 ↓
데이터 없음 ❌
 ↓
RAM에서 가져옴
```

캐시 미스가 발생하면 더 느린 메모리까지 접근해야 하기 때문에 캐시 히트보다 시간이 더 걸린다.

---

# 7. 캐시 적중률(Hit Ratio)

캐시가 얼마나 효율적으로 동작하는지 나타내는 대표적인 지표가 **캐시 적중률(Hit Ratio)**

공식은 다음과 같다.

```
캐시 적중률 =
캐시 히트 횟수
────────────────────────
캐시 히트 횟수 + 캐시 미스 횟수
```

예를 들어,

```
캐시 히트 = 90번
캐시 미스 = 10번
```

이라면,

```
적중률 = 90 / (90 + 10)
       = 0.9
       = 90%
```

즉, CPU가 요청한 데이터의 **90%를 캐시에서 찾았다**는 의미

> **일반적으로 캐시 적중률이 높을수록 CPU가 느린 메모리에 접근하는 횟수를 줄일 수 있어 성능에 유리하다.**

---

# 8. 캐시는 어떻게 사용할 데이터를 미리 예측할까?

캐시의 중요한 원리는 **참조 지역성의 원리(Locality of Reference)**

CPU가 메모리에 접근하는 패턴을 보면 완전히 무작위가 아니라 **특정한 경향성**이 나타나는 경우가 많다.

캐시는 이러한 경향성을 이용해서 CPU가 곧 사용할 가능성이 높은 데이터를 미리 가져온다.

---

# 9. 참조 지역성의 원리

참조 지역성은 크게 두 가지로 나눌 수 있다.

1. 시간 지역성(Temporal Locality)
2. 공간 지역성(Spatial Locality)

---

# 10. 시간 지역성(Temporal Locality)

시간 지역성이란

> **최근에 접근했던 메모리 공간에 다시 접근하려는 경향**



예를 들어 반복문에서 같은 변수를 계속 사용하는 경우를 생각할 수 있다.

```python
for i in range(100):
    total += i
```

`total`이나 `i`와 같이 반복적으로 사용되는 데이터는 짧은 시간 동안 여러 번 접근될 가능성이 높다.

따라서 캐시는 최근에 사용한 데이터를 다시 사용할 가능성이 높다고 판단할 수 있다.

### 💡 쉽게 말하면

> **"방금 사용한 데이터는 조금 있다가 또 사용할 가능성이 높다."**

---

# 11. 공간 지역성(Spatial Locality)

공간 지역성이란

> **최근에 접근한 메모리 공간의 주변에 있는 데이터에도 접근하려는 경향**

대표적인 예가 배열

```python
numbers = [10, 20, 30, 40, 50]
```

`numbers[0]`을 접근했다면 이후에 `numbers[1]`, `numbers[2]` 등 주변 데이터에도 접근할 가능성이 높다.

따라서 캐시는 현재 사용한 데이터뿐만 아니라 **주변에 있는 데이터도 함께 가져오는 방식**으로 효율을 높일 수 있다.

### 💡 쉽게 말하면

> **"방금 사용한 데이터 주변의 데이터도 곧 사용할 가능성이 높다."**

---

# 12. 시간 지역성 vs 공간 지역성

| 구분     | 시간 지역성            | 공간 지역성            |
| ------ | ----------------- | ----------------- |
| 의미     | 최근 사용한 데이터를 다시 사용 | 최근 사용한 데이터 주변을 사용 |
| 핵심     | 시간적으로 가까움         | 주소상으로 가까움         |
| 예시     | 반복문에서 같은 변수 반복 사용 | 배열의 연속된 요소 접근     |
| 쉽게 말하면 | "방금 쓴 걸 또 쓴다"     | "방금 쓴 것 근처를 쓴다"   |

---

# 13. 캐시 메모리의 동작 원리

전체 과정을 연결하면 다음과 같다.

```
CPU가 데이터 요청
       ↓
캐시 확인
       ↓
┌─────────────────┐
│                 │
캐시 히트       캐시 미스
│                 │
↓                 ↓
캐시에서 사용    RAM에서 가져옴
│                 │
└────────┬────────┘
         ↓
       CPU 연산
```

캐시는 **참조 지역성의 원리**를 이용해 CPU가 앞으로 사용할 가능성이 높은 데이터를 미리 가져와 저장한다.

그 결과 CPU가 필요한 데이터를 캐시에서 찾을 가능성, 즉 **캐시 적중률**을 높일 수 있다.

---

# 14. 내가 이해한 핵심 흐름

이번 메모리 단원에서 중요한 것은 각각의 개념을 따로 외우는 것이 아니라 **CPU가 데이터를 사용하는 전체 흐름**을 이해하는 것

```
CPU
 ↓
필요한 데이터 요청
 ↓
캐시 확인
 ↓
 ┌──────────────┐
 │              │
히트            미스
 │              │
 ↓              ↓
캐시 사용       RAM 접근
 │              │
 └──────┬───────┘
        ↓
      CPU 연산
```

그리고 RAM에 접근할 때 CPU는 논리 주소를 사용하고, **MMU가 이를 물리 주소로 변환**하여 실제 메모리에 접근한다.

```
CPU
 │
 │ 논리 주소
 ↓
MMU
 │
 │ 물리 주소
 ↓
RAM
```

또한 RAM에는 DRAM과 SRAM 같은 종류가 있으며,

```
DRAM → 주기억장치
SRAM → 캐시 메모리
```

와 같이 각각 다른 용도로 활용된다.

---

# ⭐ 15. 이번 단원 핵심 정리

### RAM

> **전원이 꺼지면 데이터가 사라지는 휘발성 주기억장치**

### DRAM

> **리프레시가 필요하지만 대용량으로 만들기 유리하여 주기억장치에 주로 사용**

### SRAM

> **빠르고 리프레시가 필요 없지만 비싸고 대용량으로 만들기 어려워 캐시 메모리에 주로 사용**

### SDRAM

> **클럭 신호와 동기화되어 동작하는 DRAM**

### DDR SDRAM

> **데이터 전송률을 높여 SDRAM보다 높은 대역폭을 제공하는 메모리 계열**

### 논리 주소

> **CPU와 프로그램이 사용하는 상대적인 주소**

### 물리 주소

> **실제 메모리 하드웨어가 사용하는 주소**

### MMU

> **논리 주소를 물리 주소로 변환하는 하드웨어**

### 베이스 레지스터

> **프로그램의 시작 물리 주소를 저장**

### 한계 레지스터

> **프로그램이 사용할 수 있는 논리 주소의 범위를 저장하여 메모리 접근을 보호**

### 캐시 메모리

> **CPU와 RAM 사이의 속도 차이를 줄이기 위한 빠른 메모리**

### 캐시 히트

> **CPU가 요청한 데이터가 캐시에 존재하는 경우**

### 캐시 미스

> **CPU가 요청한 데이터가 캐시에 없어 RAM 등에 접근해야 하는 경우**

### 참조 지역성

> **CPU가 메모리에 접근할 때 나타나는 일정한 경향성**

* 시간 지역성 → **최근 사용한 데이터를 다시 사용**
* 공간 지역성 → **최근 사용한 데이터 주변을 사용**

---

# 💡 한 문장으로 정리

> **CPU의 빠른 처리 속도를 최대한 활용하기 위해 컴퓨터는 RAM, 캐시, 레지스터 등의 저장 장치를 계층적으로 사용하며, MMU를 통해 논리 주소를 물리 주소로 변환하고, 캐시는 참조 지역성을 활용해 CPU가 자주 사용할 데이터를 빠르게 제공한다.**
