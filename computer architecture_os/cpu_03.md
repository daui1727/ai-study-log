# [ 03 - 1 소스 코드와 명령어 ]

## 컴퓨터는 우리가 작성한 코드를 바로 이해할까?

우리가 사용하는 Python, C 등의 프로그래밍 언어를 컴퓨터가 그대로 이해하고 실행하는 것은 아니다.

프로그래밍 언어는 크게 **고급 언어와 저급 언어**로 나눌 수 있다.

### 고급 언어

**고급 언어** : 사람이 이해하고 작성하기 편하게 만들어진 프로그래밍 언어

예: **Python, C, Java 등**

사람이 이해하기 쉽다는 장점이 있지만, CPU가 직접 이해하고 실행할 수 있는 형태는 아니다.

### 저급 언어

**저급 언어** : 컴퓨터가 직접 이해하고 실행할 수 있도록 만들어진 언어

대표적으로 **기계어와 어셈블리어**가 있다.

* **기계어** → 0과 1로 이루어진 명령어
* **어셈블리어** → 기계어를 사람이 조금 더 이해하기 쉽게 표현한 언어

```
고급 언어
Python, C, Java
      ↓
저급 언어
기계어, 어셈블리어
      ↓
CPU가 이해하고 실행
```

---

# 고급 언어를 저급 언어로 변환하는 방법

고급 언어가 저급 언어로 변환되는 대표적인 방법은 **컴파일과 인터프리트**이다.

## 컴파일

고급 언어로 작성된 **소스 코드 전체를 컴파일러가 저급 언어로 변환**하는 방식이다.

```
소스 코드
   ↓
컴파일러
   ↓
목적 코드
   ↓
실행
```

이때 컴파일이 성공하면 실행에 필요한 **목적 코드(object code)**가 생성된다.

### 컴파일의 특징

* 소스 코드 전체를 먼저 변환한 후 실행한다.
* 실행 전에 전체 코드를 확인하고 변환하기 때문에 컴파일 과정에서 오류가 발견될 수 있다.
* 컴파일이 완료된 코드를 실행하는 형태이므로 실행 과정에서 매번 소스 코드를 해석할 필요가 없다.

---

## 인터프리트

**인터프리터(interpreter)**가 소스 코드를 한 줄씩 읽고 해석하여 실행하는 방식이다.

```
소스 코드
   ↓
인터프리터
   ↓
한 줄씩 해석 및 실행
```

소스 코드 전체가 저급 언어로 변환되기를 기다릴 필요가 없다는 특징이 있다.

### 인터프리트의 특징

* 소스 코드를 한 줄씩 해석하며 실행한다.
* 실행 과정에서 오류가 발생하면 **오류가 발생한 지점 이후의 코드는 실행되지 않는다.**
* 따라서 오류가 발생하기 전까지의 코드는 실행될 수 있다.

> **컴파일** → 전체를 먼저 변환한 후 실행
> **인터프리트** → 코드를 한 줄씩 해석하며 실행

※ 실제 Python과 C 같은 언어의 동작 방식은 이보다 복잡하며, 언어를 단순히 "컴파일 언어 / 인터프리트 언어"로만 구분하는 것은 정확하지 않다. 여기서는 기본적인 개념을 이해하는 것이 목적이다.

---

# [ 03 - 2 명령어의 구조 ]

그렇다면 CPU가 실제로 실행하는 **저급 언어의 명령어**는 어떤 형태일까?

명령어는 기본적으로 다음과 같은 정보를 담고 있다.

> **"무엇을 대상으로, 어떤 연산을 수행하라."**

명령어는 크게 **연산 코드와 오퍼랜드**로 구성된다.

```
┌──────────────┬──────────────────────┐
│  연산 코드    │       오퍼랜드        │
│  무엇을 할까? │  무엇을 대상으로 할까? │
└──────────────┴──────────────────────┘
```

---

## 오퍼랜드

**오퍼랜드(operand)** : 연산에 사용할 데이터 또는 그 데이터가 저장된 위치

오퍼랜드에는 실제 데이터가 들어갈 수도 있지만, **데이터가 저장된 메모리 주소나 레지스터를 지정하는 경우가 많다.**

그래서 오퍼랜드를 **주소 필드(address field)**라고 부르기도 한다.

```
오퍼랜드
├─ 연산에 사용할 데이터
└─ 연산에 사용할 데이터가 저장된 위치
```

오퍼랜드는 명령어에 **없을 수도 있고, 하나 이상 존재할 수도 있다.**

예:

```
연산 코드
연산 코드 + 오퍼랜드 1개
연산 코드 + 오퍼랜드 2개
연산 코드 + 오퍼랜드 3개
```

---

## 연산 코드

**연산 코드(opcode)** : 명령어가 수행할 연산을 나타내는 부분

CPU마다 지원하는 명령어와 연산 코드의 종류가 다르다.

대표적인 명령어 유형은 다음과 같이 크게 나눌 수 있다.

**데이터 전송 · 산술/논리 연산 · 제어 흐름 변경 · 입출력**

> 세부적인 명령어 하나하나를 외우는 것보다 **CPU가 어떤 종류의 연산을 수행하는지**를 이해하는 것이 중요하다.

---

# 스택과 큐

명령어를 이해할 때 **스택과 큐**라는 자료구조도 알아두면 좋다.

## 스택(Stack)

**스택** : 한쪽 끝이 막혀 있어 한쪽에서만 데이터를 넣고 뺄 수 있는 자료구조

가장 나중에 들어온 데이터가 가장 먼저 나온다.

**LIFO (Last In First Out)**

```
      ↓ 데이터 추가
   ┌───────┐
   │   C   │ ← 가장 먼저 나감
   ├───────┤
   │   B   │
   ├───────┤
   │   A   │
   └───────┘
```

* **Push** → 데이터를 스택에 넣는 것
* **Pop** → 데이터를 스택에서 꺼내는 것

> **스택 = LIFO = 나중에 들어온 것이 먼저 나감**

---

## 큐(Queue)

**큐** : 양쪽 끝이 열려 있어 한쪽에서는 데이터를 넣고, 반대쪽에서는 데이터를 빼는 자료구조

가장 먼저 들어온 데이터가 가장 먼저 나온다.

**FIFO (First In First Out)**

```
데이터 입력 → [ A ][ B ][ C ] → 데이터 출력
                ↑           ↑
              먼저 들어옴   먼저 나감
```

> **큐 = FIFO = 먼저 들어온 것이 먼저 나감**

---

# 오퍼랜드는 왜 데이터를 직접 저장하지 않고 주소를 사용할까?

오퍼랜드에 연산에 사용할 데이터를 직접 저장하는 것보다 **데이터가 저장된 위치를 저장하는 경우가 많은 이유**가 있다.

명령어의 크기는 제한되어 있기 때문이다.

예를 들어 연산 코드가 일정한 크기를 차지한다면, 오퍼랜드의 개수가 많아질수록 각각의 오퍼랜드에 할당할 수 있는 공간은 줄어든다.

```
명령어 전체 크기는 제한됨

┌────────────┬──────────────┐
│  연산 코드  │  오퍼랜드     │
└────────────┴──────────────┘

오퍼랜드가 많아지면
→ 각 오퍼랜드에 할당할 공간이 줄어듦
→ 표현할 수 있는 데이터의 크기도 작아짐
```

따라서 큰 데이터를 명령어에 직접 넣기보다는 **데이터가 저장된 위치를 나타내는 주소**를 사용하는 방법이 활용된다.

> **데이터 자체를 저장하기보다는 데이터가 어디에 있는지를 저장하면 제한된 명령어 공간을 효율적으로 사용할 수 있다.**

---

# 유효 주소

**유효 주소(effective address)** : 연산에 사용할 데이터가 저장된 위치를 나타내는 주소

CPU는 명령어를 실행하면서 **연산에 사용할 데이터가 어디에 있는지 찾아야 한다.**

이때 오퍼랜드에 담긴 정보를 이용하여 유효 주소를 찾는 방법을 **주소 지정 방식**이라고 한다.

> **주소 지정 방식 = 연산에 사용할 데이터의 위치(유효 주소)를 찾는 방법**

---

# 주소 지정 방식

대표적인 주소 지정 방식은 다음과 같다.

**즉시 주소 지정 · 직접 주소 지정 · 간접 주소 지정 · 레지스터 주소 지정 · 레지스터 간접 주소 지정**

---

## 1. 즉시 주소 지정 방식

**연산에 사용할 데이터를 오퍼랜드 필드에 직접 명시하는 방식**

```
[ 연산 코드 ][ 데이터 ]
```

예를 들어 CPU에게 "5를 더하라"라고 명령한다면 `5`라는 값 자체가 오퍼랜드에 들어가는 방식이다.

가장 간단한 형태이며 메모리에 접근할 필요가 없기 때문에 비교적 빠르다.

하지만 오퍼랜드 필드의 크기가 제한되어 있기 때문에 **표현할 수 있는 데이터의 크기가 작다는 단점**이 있다.

> **즉시 주소 지정 = 데이터 자체를 오퍼랜드에 저장**

---

## 2. 직접 주소 지정 방식

**오퍼랜드 필드에 유효 주소를 직접 명시하는 방식**

```
[ 연산 코드 ][ 메모리 주소 ]
                    ↓
                  데이터
```

오퍼랜드에 데이터가 저장된 **메모리 주소 자체**를 저장한다.

즉시 주소 지정 방식보다 큰 데이터를 사용할 수 있지만, 오퍼랜드 필드의 크기가 제한되어 있기 때문에 **표현할 수 있는 메모리 주소의 범위에도 제한**이 생긴다.

> **직접 주소 지정 = 오퍼랜드에 데이터가 저장된 주소를 직접 저장**

---

## 3. 간접 주소 지정 방식

**오퍼랜드 필드에 유효 주소가 저장된 메모리의 주소를 명시하는 방식**

```
[ 연산 코드 ][ 주소 ]
                  ↓
             다른 메모리 주소
                  ↓
                데이터
```

주소를 한 번 더 따라가야 하기 때문에 직접 주소 지정 방식보다 **메모리 접근 횟수가 많아져 상대적으로 느릴 수 있다.**

하지만 직접 주소 지정 방식보다 **더 넓은 주소 범위를 표현할 수 있다는 장점**이 있다.

> **간접 주소 지정 = 주소가 저장된 위치를 오퍼랜드에 저장**

---

## 4. 레지스터 주소 지정 방식

**연산에 사용할 데이터가 저장된 레지스터를 오퍼랜드에 명시하는 방식**

```
[ 연산 코드 ][ 레지스터 ]
                  ↓
               데이터
```

레지스터는 CPU 내부에 있기 때문에 메모리에 접근하는 것보다 **레지스터에 접근하는 것이 일반적으로 빠르다.**

> **레지스터 주소 지정 = 데이터가 저장된 레지스터를 지정**

---

## 5. 레지스터 간접 주소 지정 방식

**데이터가 저장된 메모리의 주소를 레지스터에 저장하고, 그 레지스터를 오퍼랜드에 명시하는 방식**

```
[ 연산 코드 ][ 레지스터 ]
                  ↓
             메모리 주소
                  ↓
                데이터
```

레지스터에는 실제 데이터가 아니라 **데이터가 저장된 메모리의 주소**가 들어 있다.

> **레지스터 간접 주소 지정 = 레지스터가 가지고 있는 주소를 이용해 메모리의 데이터에 접근**

---

# 주소 지정 방식 한눈에 비교

| 방식          | 오퍼랜드에 들어가는 것      | 특징               |
| ----------- | ----------------- | ---------------- |
| **즉시**      | 데이터 자체            | 빠르지만 데이터 크기가 작음  |
| **직접**      | 데이터가 저장된 메모리 주소   | 주소를 직접 지정        |
| **간접**      | 유효 주소가 저장된 메모리 주소 | 메모리 접근이 한 번 더 필요 |
| **레지스터**    | 데이터가 저장된 레지스터     | 메모리보다 빠른 레지스터 사용 |
| **레지스터 간접** | 주소가 저장된 레지스터      | 레지스터를 통해 메모리 접근  |

### 핵심 흐름

```
즉시
오퍼랜드 → 데이터

직접
오퍼랜드 → 메모리 주소 → 데이터

간접
오퍼랜드 → 메모리 주소 → 메모리 주소 → 데이터

레지스터
오퍼랜드 → 레지스터 → 데이터

레지스터 간접
오퍼랜드 → 레지스터 → 메모리 주소 → 데이터
```

# 핵심만 기억하기

> **고급 언어** → 사람이 이해하고 작성하기 쉬운 언어
> **저급 언어** → 컴퓨터가 이해하고 실행하기 위한 언어
> **컴파일** → 소스 코드 전체를 저급 언어로 변환한 후 실행
> **인터프리트** → 소스 코드를 한 줄씩 해석하며 실행
> **명령어** → 연산 코드 + 오퍼랜드
> **연산 코드** → 무엇을 수행할지 나타냄
> **오퍼랜드** → 연산에 사용할 데이터 또는 데이터가 저장된 위치
> **스택** → LIFO, 나중에 들어온 것이 먼저 나감
> **큐** → FIFO, 먼저 들어온 것이 먼저 나감
> **유효 주소** → 연산에 사용할 데이터가 저장된 위치
> **주소 지정 방식** → 유효 주소를 찾는 방법
