# [ 10 - 1 프로세스 개요 ] 💡

## 1. 프로세스란?

**프로세스(Process) = 실행 중인 프로그램**

보조기억장치에 저장된 프로그램을 실행하면 메모리에 적재되고, **실행 중인 프로그램인 프로세스**가 된다.

> 프로그램은 실행되기 전에는 단순한 파일이고, 실행되는 순간 프로세스가 된다.

### 포그라운드 vs 백그라운드

| 구분             | 설명                                  | 예시                    |
| -------------- | ----------------------------------- | --------------------- |
| **포그라운드 프로세스** | 사용자가 화면에서 직접 상호작용하며 사용하는 프로세스       | 웹 브라우저, 메모장           |
| **백그라운드 프로세스** | 사용자가 직접 보지 않는 상태에서도 실행되는 프로세스       | 시스템 작업, 서버 프로그램       |
| **서비스 / 데몬**   | 사용자와 직접 상호작용하지 않고 백그라운드에서 특정 작업을 수행 | Windows 서비스, Linux 데몬 |

---

## 2. 운영체제는 프로세스를 어떻게 관리할까?

모든 프로세스는 실행을 위해 **CPU가 필요**하다.

하지만 CPU는 한정되어 있기 때문에 여러 프로세스가 CPU를 동시에 계속 사용할 수는 없다.

따라서 운영체제는 CPU를 여러 프로세스에 **일정 시간씩 나누어 할당**한다.

```
프로세스 A 실행
      ↓
프로세스 B 실행
      ↓
프로세스 C 실행
      ↓
다시 프로세스 A 실행
      ↓
빠르게 반복
```

프로세스가 CPU를 사용하는 동안 **타이머 인터럽트(타임아웃 인터럽트)**&#xAC00; 발생하면 CPU 사용 시간이 끝났음을 알리고, 운영체제는 다른 프로세스에게 CPU를 할당할 수 있다.

> 우리가 여러 프로그램을 동시에 실행하는 것처럼 느끼는 이유도 CPU가 프로세스들을 매우 빠르게 번갈아 실행하기 때문이다.

---

## 3. 프로세스 제어 블록(PCB)

운영체제가 수많은 프로세스를 관리하려면 각 프로세스의 정보를 저장해 두어야 한다.

이때 사용하는 자료구조가 **프로세스 제어 블록(PCB, Process Control Block)**&#xC774;다.

**PCB = 프로세스의 정보를 저장하는 자료구조**

* 프로세스가 생성되면 **커널 영역**에 PCB가 생성된다.
* 프로세스가 종료되면 PCB도 폐기된다.
* 쉽게 말하면 프로세스에 붙어 있는 **관리용 정보 태그**와 같다.

### PCB에 저장되는 주요 정보

| 정보              | 의미                                |
| --------------- | --------------------------------- |
| **PID**         | 프로세스를 식별하기 위한 고유 번호               |
| **레지스터 값**      | 실행을 이어가기 위해 필요한 CPU 레지스터의 값       |
| **프로세스 상태**     | 현재 프로세스가 실행/대기/준비 등의 어떤 상태인지      |
| **CPU 스케줄링 정보** | CPU를 언제, 어떤 순서로 할당받을지에 대한 정보      |
| **메모리 정보**      | 프로세스가 사용하는 메모리 위치 및 페이지 테이블 등의 정보 |
| **파일·입출력 정보**   | 사용 중인 파일과 입출력장치 등의 정보             |

### 특히 중요한 것 → 레지스터 값

프로세스 A가 CPU를 사용하다가 CPU 사용 시간이 끝나면, 현재까지 실행한 상태를 저장해 두어야 한다.

예를 들어 **프로그램 카운터(PC), 스택 포인터(SP)** 등의 레지스터 값을 PCB에 저장한다.

```
프로세스 A 실행
    ↓
레지스터 값 저장 → PCB
    ↓
다른 프로세스 실행
    ↓
다시 A의 차례
    ↓
PCB에 저장된 레지스터 값 복원
    ↓
A의 실행을 이어서 진행
```

즉, PCB는 **프로세스가 어디까지 실행되었는지 이어서 실행하기 위한 정보를 관리**한다고 이해하면 된다.

## 4. 문맥 교환(Con Switch)

프로세스 A를 실행하다가 프로세스 B를 실행하려면 A의 현재 상태를 저장하고 B의 상태를 불러와야 한다.

이때 **프로세스의 실행 상태를 문맥(Con)**&#xC774;라고 한다.

그리고 A의 문맥을 저장하고 B의 문맥을 복원하는 과정을 **문맥 교환(Con Switch)**&#xC774;라고 한다.

```
프로세스 A 실행
      ↓
A의 문맥 백업
      ↓
B의 문맥 복구
      ↓
프로세스 B 실행
```

### 문맥에 포함되는 정보

대표적으로 **프로그램 카운터, 레지스터 값, 프로세스 상태, 메모리 관련 정보** 등이 있다.

> 문맥 교환이 있기 때문에 여러 프로세스가 CPU를 빠르게 번갈아 사용하면서 동시에 실행되는 것처럼 보인다.

⚠️ 문맥 교환도 CPU가 수행해야 하는 작업이므로 **문맥 교환이 너무 자주 발생하면 성능에 부담**이 될 수 있다.

# 5. 프로세스의 메모리 구조

프로세스가 메모리에 적재되면 일반적으로 다음과 같은 영역으로 구성된다.

```
높은 주소
┌──────────────┐
│    스택      │ ← 지역 변수, 매개변수 등
├──────────────┤
│      ↓       │
│              │
│      ↑       │
├──────────────┤
│     힙       │ ← 동적으로 할당되는 데이터
├──────────────┤
│    데이터    │ ← 전역 변수, 정적 변수 등
├──────────────┤
│    코드      │ ← 실행할 명령어
└──────────────┘
낮은 주소
```

### 코드 영역(Code/)

프로그램이 실행할 **코드(기계어 명령어)**&#xAC00; 저장되는 영역이다.

* CPU가 실행할 명령어 저장
* 일반적으로 쓰기가 제한된 **읽기 전용 영역**

### 데이터 영역(Data)

프로그램이 실행되는 동안 계속 유지되어야 하는 데이터를 저장한다.

* 전역 변수
* 정적 변수 등

### 힙 영역(Heap)

프로그래머가 필요에 따라 **동적으로 메모리를 할당**하는 영역이다.

* 동적 할당 데이터 저장
* 일반적으로 낮은 주소 → 높은 주소 방향으로 증가

### 스택 영역(Stack)

함수 호출 과정에서 **일시적으로 사용되는 데이터**를 저장한다.

* 매개변수
* 지역 변수
* 함수 호출 정보 등
* 일반적으로 높은 주소 → 낮은 주소 방향으로 증가

> 힙과 스택은 실행 중 크기가 변할 수 있기 때문에 **동적 할당 영역**, 코드와 데이터 영역은 일반적으로 **정적 할당 영역**으로 구분한다.

---

## 6. 힙과 메모리 누수

힙 영역에서 동적으로 메모리를 할당했다면, 더 이상 필요하지 않은 메모리를 적절히 해제해야 한다.

**메모리 누수(Memory Leak)**
→ 사용하지 않는 메모리가 계속 점유되어 다른 곳에서 사용할 수 없게 되는 현상

언어에 따라 메모리 관리 방식이 다르다.

* **C** → 개발자가 직접 메모리를 할당하고 해제해야 함
* **Python, Java 등** → 가비지 컬렉터가 사용하지 않는 객체의 메모리를 자동으로 관리

따라서 C에서 할당한 메모리를 제대로 해제하지 않으면 **메모리 누수**가 발생할 수 있다.

## 🔗 전체 흐름 정리

```
프로그램
  ↓ 실행
프로세스
  ↓
CPU가 실행
  ↓
CPU는 한정되어 있음
  ↓
프로세스마다 CPU를 일정 시간씩 할당
  ↓
프로세스 전환 필요
  ↓
PCB에 현재 문맥 저장
  ↓
다음 프로세스의 문맥 복구
  ↓
문맥 교환(Con Switch)
  ↓
여러 프로세스가 빠르게 번갈아 실행
```

### ⭐ 핵심 정리

> **프로세스 = 실행 중인 프로그램**

> **PCB = 운영체제가 프로세스를 관리하기 위한 정보 묶음**

> **문맥(Con) = 프로세스를 이어서 실행하기 위해 필요한 현재 상태**

> **문맥 교환 = 기존 프로세스의 문맥을 저장하고 다음 프로세스의 문맥을 복원하는 과정**

> **프로세스 메모리 = 코드 + 데이터 + 힙 + 스택**

그리고 이 내용은 다음에 배울 **프로세스 상태, 프로세스 계층 구조, 스레드, CPU 스케줄링**을 이해하는 기반이 된다.

# [ 10 - 2 프로세스 상태와 계층 구조 ]

10-1에서 프로세스는 **실행 중인 프로그램**이고, 운영체제는 PCB를 이용해 프로세스를 관리한다고 배웠다.

그렇다면 프로세스는 실행되는 동안 어떤 상태를 거칠까?

## 1. 프로세스 상태

프로세스는 실행되는 동안 **생성 → 준비 → 실행 → 대기 → 종료** 등의 상태를 오간다.

| 상태     | 설명                                    |
| ------ | ------------------------------------- |
| **생성** | 프로세스가 생성되고 메모리에 적재되며 PCB가 만들어지는 상태    |
| **준비** | CPU를 할당받으면 바로 실행할 수 있지만, CPU를 기다리는 상태 |
| **실행** | CPU를 할당받아 실제로 실행 중인 상태                |
| **대기** | 입출력 작업 등 특정 작업이 끝나기를 기다리는 상태          |
| **종료** | 실행이 끝나 메모리와 PCB 등의 자원이 정리되는 상태        |

### 🔄 상태가 어떻게 바뀔까?

```
             CPU 할당
        ┌──────────────→ 실행
        │                 │
        │                 │ CPU 사용 시간 종료
        │                 ↓
      준비 ←───────────────┘
        ↑
        │ I/O 완료
        │
       대기
        ↑
        │ I/O 요청
        └──── 실행

생성 → 준비 → 실행 → 종료
```

**준비 → 실행**으로 전환되어 CPU를 할당받는 것을 **디스패치(Dispatch)**&#xB77C;고 한다.

실행 중인 프로세스가 CPU 사용 시간을 모두 사용하면 **타이머 인터럽트**에 의해 다시 준비 상태로 돌아갈 수 있다.

또한 실행 중에 입출력을 요청하면 CPU보다 느린 입출력 작업이 끝날 때까지 **대기 상태**로 들어간다.

> 핵심은 **프로세스가 CPU를 계속 붙잡고 있는 것이 아니라, 상황에 따라 상태를 바꾸면서 실행된다**는 것이다.

# 2. 프로세스 계층 구조

프로세스는 실행 도중 **시스템 호출을 통해 새로운 프로세스를 생성**할 수 있다.

* 새로운 프로세스를 만든 프로세스 → **부모 프로세스**
* 부모 프로세스가 생성한 프로세스 → **자식 프로세스**

부모와 자식은 서로 **별개의 프로세스**이므로 각각 다른 PID를 가진다.

```
부모 프로세스 (PID 100)
├── 자식 프로세스 (PID 101)
│   ├── 자식 프로세스 (PID 103)
│   └── 자식 프로세스 (PID 104)
└── 자식 프로세스 (PID 102)
```

자식 프로세스 역시 새로운 프로세스를 만들 수 있기 때문에 **프로세스 계층 구조**가 만들어진다.

일부 운영체제에서는 자식 프로세스가 부모 프로세스의 PID인 **PPID(Parent PID)**&#xB3C4; 관리한다.

> Windows에서는 Linux처럼 프로세스 계층 구조가 핵심 개념으로 다뤄지지는 않는다.

# 3. 프로세스 생성 : `fork()`와 `exec()`

그렇다면 부모 프로세스는 자식 프로세스를 어떻게 만들고, 자식 프로세스는 어떻게 다른 프로그램을 실행할까?

대표적인 방법이 **`fork()` → `exec()`**이다.

### `fork()` : 복제

부모 프로세스가 `fork()` 시스템 호출을 하면 **부모 프로세스를 바탕으로 자식 프로세스가 생성**된다.

```
부모 프로세스
      │
    fork()
      ↓
부모 프로세스 + 자식 프로세스
```

자식 프로세스는 부모의 실행 환경과 자원을 바탕으로 만들어진다.

### `exec()` : 옷 갈아입기

자식 프로세스가 `exec()`를 호출하면 자신의 메모리 공간을 **새로운 프로그램으로 교체**한다.

```
fork()
  ↓
부모를 바탕으로 자식 생성
  ↓
exec()
  ↓
자식 프로세스가 새로운 프로그램 실행
```

즉,

> **fork = 프로세스 복제**
> **exec = 실행할 프로그램 교체**

라고 이해하면 된다.

# [ 10 - 3 스레드 ]

## 1. 스레드란?

**스레드(Thread) = 프로세스를 구성하는 실행 흐름의 단위**

하나의 프로세스는 하나 이상의 스레드를 가질 수 있다.

```
단일 스레드 프로세스
└── 실행 흐름 1

멀티스레드 프로세스
├── 실행 흐름 1
├── 실행 흐름 2
└── 실행 흐름 3
```

즉, **프로세스 하나에서 여러 실행 흐름을 만들 수 있고**, 이것을 멀티스레드라고 한다.

---

## 2. 스레드는 어떻게 따로 실행될까?

각 스레드는 자신의 실행을 이어가기 위해 **스레드 ID, 프로그램 카운터(PC), 레지스터 값, 스택** 등의 정보를 가진다.

그래서 같은 프로세스 안에 있더라도 각각 **어디까지 실행할지, 어떤 함수를 실행할지**를 독립적으로 관리할 수 있다.

```
하나의 프로세스
┌─────────────────────────┐
│ 코드 / 데이터 / 힙 공유 │
│                         │
│ 스레드 1 → PC + 스택    │
│ 스레드 2 → PC + 스택    │
│ 스레드 3 → PC + 스택    │
└─────────────────────────┘
```

반면 **코드·데이터·힙 등의 프로세스 자원은 스레드들이 공유**한다.

예를 들어 프로세스가 어떤 파일을 열었다면 같은 프로세스에 속한 여러 스레드가 해당 자원에 접근할 수 있다.

> **스레드 = 각자 실행 흐름은 가지고 있지만, 프로세스의 자원은 함께 사용하는 존재**

---

# 3. 멀티프로세스 vs 멀티스레드

같은 작업을 처리한다고 생각해보자.

### 멀티프로세스

**프로세스를 여러 개 만들어 각각 작업**

```
프로세스 A ── 작업
프로세스 B ── 작업
프로세스 C ── 작업
```

각 프로세스는 기본적으로 **독립된 메모리 공간**을 사용한다.

### 멀티스레드

**하나의 프로세스 안에서 여러 스레드가 작업**

```
        하나의 프로세스
┌───────────────────────┐
│ 스레드 A ── 작업       │
│ 스레드 B ── 작업       │
│ 스레드 C ── 작업       │
│                       │
│ 코드 / 데이터 / 힙 공유 │
└───────────────────────┘
```

### 한눈에 비교

| 구분    | 멀티프로세스                       | 멀티스레드                  |
| ----- | ---------------------------- | ---------------------- |
| 실행 단위 | 여러 프로세스                      | 여러 스레드                 |
| 메모리   | 기본적으로 서로 독립                  | 같은 프로세스의 자원 공유         |
| 통신    | IPC 필요                       | 공유 자원 이용이 상대적으로 쉬움     |
| 장점    | 한 프로세스의 문제가 다른 프로세스에 영향을 덜 줌 | 자원 공유가 쉽고 협력에 유리       |
| 주의점   | 프로세스 간 통신이 상대적으로 복잡          | 공유 자원 때문에 동기화 문제 발생 가능 |

프로세스끼리도 **IPC(프로세스 간 통신)**&#xB97C; 이용하면 데이터를 주고받을 수 있다.

대표적으로 **파일, 공유 메모리** 등을 이용할 수 있다.

따라서 단순히 **“프로세스는 통신이 불가능하고 스레드는 가능하다”**&#xAC00; 아니라,

> **프로세스는 기본적으로 자원을 공유하지 않기 때문에 통신에 별도의 방법이 필요하고, 스레드는 같은 프로세스의 자원을 공유하기 때문에 통신과 협력이 상대적으로 쉽다.**

라고 이해하는 것이 정확하다.

# 🔗 10장의 전체 흐름

```
프로세스
  ↓
실행되는 동안 여러 상태를 가짐
  ↓
생성 → 준비 → 실행 → 대기 → 종료
  ↓
프로세스는 다른 프로세스를 만들 수 있음
  ↓
부모 프로세스 → 자식 프로세스
  ↓
fork()로 프로세스 생성
  ↓
exec()로 새로운 프로그램 실행
  ↓
하나의 프로세스 안에서도
여러 실행 흐름을 만들 수 있음
  ↓
스레드
  ↓
멀티스레드
  ↓
프로세스의 자원 공유
  ↓
빠른 협력 가능
  ↓
동시에 접근하면 동기화 문제 발생
```

## ⭐ 꼭 기억할 것

> **프로세스 = 자원을 가지고 실행되는 프로그램**

> **스레드 = 프로세스 내부의 실행 흐름**

> **프로세스 상태 = 생성 → 준비 → 실행 → 대기 → 종료**

> **fork() = 프로세스를 생성하는 대표적인 시스템 호출**

> **exec() = 프로세스가 실행할 프로그램을 교체하는 시스템 호출**

> **멀티프로세스 = 여러 프로세스가 작업**

> **멀티스레드 = 하나의 프로세스 안에서 여러 스레드가 작업**

> **프로세스는 기본적으로 자원을 공유하지 않고, 스레드는 같은 프로세스의 자원을 공유한다.**
