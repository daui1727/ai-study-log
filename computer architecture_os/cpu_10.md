# [ 10 - 1 프로세스 개요 ] 💡

## 1. 프로세스란?

**프로세스(Process) = 실행 중인 프로그램**

보조기억장치에 저장된 프로그램을 실행하면 메모리에 적재되고, **실행 중인 프로그램인 프로세스**가 된다.

> 프로그램은 실행되기 전에는 단순한 파일이고, 실행되는 순간 프로세스가 된다.

### 포그라운드 vs 백그라운드

| 구분             | 설명                                  | 예시                    |
| -------------- | ----------------------------------- | --------------------- |
| **포그라운드 프로세스** | 사용자가 화면에서 직접 상호작용하며 사용하는 프로세스       | 웹 브라우저, 메모장           |
| **백그라운드 프로세스** | 사용자가 직접 보지 않는 상태에서도 실행되는 프로세스       | 시스템 작업, 서버 프로그램       |
| **서비스 / 데몬**   | 사용자와 직접 상호작용하지 않고 백그라운드에서 특정 작업을 수행 | Windows 서비스, Linux 데몬 |

---

## 2. 운영체제는 프로세스를 어떻게 관리할까?

모든 프로세스는 실행을 위해 **CPU가 필요**하다.

하지만 CPU는 한정되어 있기 때문에 여러 프로세스가 CPU를 동시에 계속 사용할 수는 없다.

따라서 운영체제는 CPU를 여러 프로세스에 **일정 시간씩 나누어 할당**한다.

```
프로세스 A 실행
      ↓
프로세스 B 실행
      ↓
프로세스 C 실행
      ↓
다시 프로세스 A 실행
      ↓
빠르게 반복
```

프로세스가 CPU를 사용하는 동안 **타이머 인터럽트(타임아웃 인터럽트)**&#xAC00; 발생하면 CPU 사용 시간이 끝났음을 알리고, 운영체제는 다른 프로세스에게 CPU를 할당할 수 있다.

> 우리가 여러 프로그램을 동시에 실행하는 것처럼 느끼는 이유도 CPU가 프로세스들을 매우 빠르게 번갈아 실행하기 때문이다.

---

## 3. 프로세스 제어 블록(PCB)

운영체제가 수많은 프로세스를 관리하려면 각 프로세스의 정보를 저장해 두어야 한다.

이때 사용하는 자료구조가 **프로세스 제어 블록(PCB, Process Control Block)**&#xC774;다.

**PCB = 프로세스의 정보를 저장하는 자료구조**

* 프로세스가 생성되면 **커널 영역**에 PCB가 생성된다.
* 프로세스가 종료되면 PCB도 폐기된다.
* 쉽게 말하면 프로세스에 붙어 있는 **관리용 정보 태그**와 같다.

### PCB에 저장되는 주요 정보

| 정보              | 의미                                |
| --------------- | --------------------------------- |
| **PID**         | 프로세스를 식별하기 위한 고유 번호               |
| **레지스터 값**      | 실행을 이어가기 위해 필요한 CPU 레지스터의 값       |
| **프로세스 상태**     | 현재 프로세스가 실행/대기/준비 등의 어떤 상태인지      |
| **CPU 스케줄링 정보** | CPU를 언제, 어떤 순서로 할당받을지에 대한 정보      |
| **메모리 정보**      | 프로세스가 사용하는 메모리 위치 및 페이지 테이블 등의 정보 |
| **파일·입출력 정보**   | 사용 중인 파일과 입출력장치 등의 정보             |

### 특히 중요한 것 → 레지스터 값

프로세스 A가 CPU를 사용하다가 CPU 사용 시간이 끝나면, 현재까지 실행한 상태를 저장해 두어야 한다.

예를 들어 **프로그램 카운터(PC), 스택 포인터(SP)** 등의 레지스터 값을 PCB에 저장한다.

```
프로세스 A 실행
    ↓
레지스터 값 저장 → PCB
    ↓
다른 프로세스 실행
    ↓
다시 A의 차례
    ↓
PCB에 저장된 레지스터 값 복원
    ↓
A의 실행을 이어서 진행
```

즉, PCB는 **프로세스가 어디까지 실행되었는지 이어서 실행하기 위한 정보를 관리**한다고 이해하면 된다.

## 4. 문맥 교환(Con Switch)

프로세스 A를 실행하다가 프로세스 B를 실행하려면 A의 현재 상태를 저장하고 B의 상태를 불러와야 한다.

이때 **프로세스의 실행 상태를 문맥(Con)**&#xC774;라고 한다.

그리고 A의 문맥을 저장하고 B의 문맥을 복원하는 과정을 **문맥 교환(Con Switch)**&#xC774;라고 한다.

```
프로세스 A 실행
      ↓
A의 문맥 백업
      ↓
B의 문맥 복구
      ↓
프로세스 B 실행
```

### 문맥에 포함되는 정보

대표적으로 **프로그램 카운터, 레지스터 값, 프로세스 상태, 메모리 관련 정보** 등이 있다.

> 문맥 교환이 있기 때문에 여러 프로세스가 CPU를 빠르게 번갈아 사용하면서 동시에 실행되는 것처럼 보인다.

⚠️ 문맥 교환도 CPU가 수행해야 하는 작업이므로 **문맥 교환이 너무 자주 발생하면 성능에 부담**이 될 수 있다.

# 5. 프로세스의 메모리 구조

프로세스가 메모리에 적재되면 일반적으로 다음과 같은 영역으로 구성된다.

```
높은 주소
┌──────────────┐
│    스택      │ ← 지역 변수, 매개변수 등
├──────────────┤
│      ↓       │
│              │
│      ↑       │
├──────────────┤
│     힙       │ ← 동적으로 할당되는 데이터
├──────────────┤
│    데이터    │ ← 전역 변수, 정적 변수 등
├──────────────┤
│    코드      │ ← 실행할 명령어
└──────────────┘
낮은 주소
```

### 코드 영역(Code/)

프로그램이 실행할 **코드(기계어 명령어)**&#xAC00; 저장되는 영역이다.

* CPU가 실행할 명령어 저장
* 일반적으로 쓰기가 제한된 **읽기 전용 영역**

### 데이터 영역(Data)

프로그램이 실행되는 동안 계속 유지되어야 하는 데이터를 저장한다.

* 전역 변수
* 정적 변수 등

### 힙 영역(Heap)

프로그래머가 필요에 따라 **동적으로 메모리를 할당**하는 영역이다.

* 동적 할당 데이터 저장
* 일반적으로 낮은 주소 → 높은 주소 방향으로 증가

### 스택 영역(Stack)

함수 호출 과정에서 **일시적으로 사용되는 데이터**를 저장한다.

* 매개변수
* 지역 변수
* 함수 호출 정보 등
* 일반적으로 높은 주소 → 낮은 주소 방향으로 증가

> 힙과 스택은 실행 중 크기가 변할 수 있기 때문에 **동적 할당 영역**, 코드와 데이터 영역은 일반적으로 **정적 할당 영역**으로 구분한다.

---

## 6. 힙과 메모리 누수

힙 영역에서 동적으로 메모리를 할당했다면, 더 이상 필요하지 않은 메모리를 적절히 해제해야 한다.

**메모리 누수(Memory Leak)**
→ 사용하지 않는 메모리가 계속 점유되어 다른 곳에서 사용할 수 없게 되는 현상

언어에 따라 메모리 관리 방식이 다르다.

* **C** → 개발자가 직접 메모리를 할당하고 해제해야 함
* **Python, Java 등** → 가비지 컬렉터가 사용하지 않는 객체의 메모리를 자동으로 관리

따라서 C에서 할당한 메모리를 제대로 해제하지 않으면 **메모리 누수**가 발생할 수 있다.

## 🔗 전체 흐름 정리

```
프로그램
  ↓ 실행
프로세스
  ↓
CPU가 실행
  ↓
CPU는 한정되어 있음
  ↓
프로세스마다 CPU를 일정 시간씩 할당
  ↓
프로세스 전환 필요
  ↓
PCB에 현재 문맥 저장
  ↓
다음 프로세스의 문맥 복구
  ↓
문맥 교환(Con Switch)
  ↓
여러 프로세스가 빠르게 번갈아 실행
```

### ⭐ 핵심 정리

> **프로세스 = 실행 중인 프로그램**

> **PCB = 운영체제가 프로세스를 관리하기 위한 정보 묶음**

> **문맥(Con) = 프로세스를 이어서 실행하기 위해 필요한 현재 상태**

> **문맥 교환 = 기존 프로세스의 문맥을 저장하고 다음 프로세스의 문맥을 복원하는 과정**

> **프로세스 메모리 = 코드 + 데이터 + 힙 + 스택**

그리고 이 내용은 다음에 배울 **프로세스 상태, 프로세스 계층 구조, 스레드, CPU 스케줄링**을 이해하는 기반이 된다.

# [ 10 - 2 프로세스 상태와 계층 구조 ]

## 1. 프로세스 상태

프로세스는 실행되는 동안 계속 CPU를 사용하는 것이 아니라, 상황에 따라 여러 상태를 오간다.

### 프로세스의 5가지 대표 상태

| 상태                      | 의미                                    |
| ----------------------- | ------------------------------------- |
| **생성(New)**             | 프로세스가 생성되고 PCB가 만들어지는 상태              |
| **준비(Ready)**           | CPU를 할당받으면 바로 실행할 수 있지만, CPU를 기다리는 상태 |
| **실행(Running)**         | CPU를 할당받아 실제로 실행 중인 상태                |
| **대기(Waiting/Blocked)** | 입출력이나 특정 이벤트가 완료되기를 기다리는 상태           |
| **종료(Terminated)**      | 실행이 끝나 자원과 PCB가 정리되는 상태               |

### 🔄 프로세스 상태 변화

```
              CPU 할당
        ┌────────────────┐
        ↓                │
     [준비] ─────────→ [실행]
        ↑                │
        │                │ I/O 요청
        │                ↓
        └──────────── [대기]
        
[생성] ─→ [준비]

[실행] ─→ [종료]
```

실행 중인 프로세스가 **CPU 사용 시간을 모두 사용하면 준비 상태로 돌아가고**, 입출력 작업을 요청하면 대기 상태로 이동할 수 있다.

> **핵심:** 프로세스는 `실행 ↔ 준비 ↔ 대기`를 반복하면서 작업을 수행한다.

## 2. 프로세스 계층 구조

운영체제에서 프로세스는 서로 독립적으로 존재하기도 하지만, **부모 프로세스와 자식 프로세스 관계**를 이루기도 한다.

```
부모 프로세스
├── 자식 프로세스
│   ├── 자식 프로세스
│   └── 자식 프로세스
└── 자식 프로세스
```

이처럼 프로세스가 **트리 형태의 계층 구조**를 이루는 것을 프로세스 계층 구조라고 한다.

각 프로세스는 **PID(Process ID)**&#xB77C;는 고유한 번호를 가지고 있으며, 부모 프로세스의 PID를 가리키는 **PPID(Parent PID)**&#xB97C; 통해 부모 관계를 확인할 수 있다.

### Linux의 프로세스 생성

Linux에서는 대표적으로 다음과 같은 시스템 호출을 사용한다.

**`fork()`**

→ 현재 프로세스를 바탕으로 새로운 **자식 프로세스**를 생성한다.

**`exec()`**

→ 현재 프로세스가 실행할 프로그램을 **새로운 프로그램으로 교체**한다.

```
fork()
부모 프로세스
      ↓
부모 + 자식 프로세스 생성
      ↓
자식 프로세스에서 exec()
      ↓
다른 프로그램 실행
```

> `fork()`는 **프로세스를 만드는 것**, `exec()`는 **실행할 프로그램을 교체하는 것**으로 구분하면 된다.

# [ 10 - 3 스레드 ]

## 1. 스레드란?

**스레드(Thread) = 프로세스에서 실제로 실행되는 흐름의 단위**

프로세스가 **실행 중인 프로그램**이라면, 스레드는 그 프로세스 안에서 **실제로 작업을 수행하는 실행 흐름**이라고 이해하면 쉽다.

하나의 프로세스는 **하나의 스레드**를 가질 수도 있고, **여러 개의 스레드**를 가질 수도 있다.

```
프로세스
┌─────────────────────────┐
│ 코드 / 데이터 / 힙 공유 │
│                         │
│ 스레드 1 ── Stack + PC  │
│ 스레드 2 ── Stack + PC  │
│ 스레드 3 ── Stack + PC  │
└─────────────────────────┘
```

---

## 2. 프로세스와 스레드의 메모리 구조

### 프로세스

프로세스들은 기본적으로 **서로 독립된 메모리 공간**을 가진다.

```
프로세스 A                 프로세스 B
┌──────────┐              ┌──────────┐
│ 코드     │              │ 코드     │
│ 데이터   │              │ 데이터   │
│ 힙       │              │ 힙       │
│ 스택     │              │ 스택     │
└──────────┘              └──────────┘
      ↕ 서로 독립된 공간 ↕
```

따라서 A의 데이터를 B가 직접 변경할 수 없다.

### 스레드

같은 프로세스에 속한 스레드들은 **코드·데이터·힙 영역을 공유**한다.

대신 각 스레드는 자신의 실행을 관리하기 위해 **스택과 레지스터(특히 PC)**&#xB97C; 별도로 가진다.

| 구분      | 프로세스     | 스레드            |
| ------- | -------- | -------------- |
| 코드      | 독립       | **공유**         |
| 데이터     | 독립       | **공유**         |
| 힙       | 독립       | **공유**         |
| 스택      | 독립       | **각자 별도**      |
| PC/레지스터 | 별도       | **각자 별도**      |
| 자원 공유   | 상대적으로 적음 | 같은 프로세스 내에서 많음 |

> **프로세스 = 자원을 묶어 관리하는 단위**
> **스레드 = CPU가 실행하는 작업의 흐름**

---

## 3. 멀티스레드

하나의 프로세스 안에서 **여러 스레드가 동시에 실행되는 것처럼 동작**하도록 하는 것을 멀티스레드라고 한다.

예를 들어 웹 브라우저에서:

```
웹 브라우저 프로세스
├── 화면 처리 스레드
├── 네트워크 작업 스레드
├── 사용자 입력 처리 스레드
└── 기타 작업 스레드
```

여러 스레드가 코드·데이터·힙을 공유하기 때문에 **프로세스 간 통신(IPC)보다 데이터를 공유하기가 상대적으로 쉽고 빠르다.**

하지만 공유 자원에 여러 스레드가 동시에 접근하면 문제가 발생할 수 있다.

### Race Condition(경쟁 조건)

여러 스레드가 **공유 데이터를 동시에 읽거나 수정**하면서 실행 순서에 따라 결과가 달라지는 문제이다.

따라서 멀티스레드에서는 **동기화(Synchronization)**&#xAC00; 중요하다.

또한 하나의 프로세스 안에서 스레드들이 자원을 공유하기 때문에 **한 스레드의 오류가 같은 프로세스의 다른 스레드에도 영향을 줄 수 있다.**

# [ 10 - 추가 ] Python으로 프로세스와 스레드 확인하기

## 1. 멀티프로세스 — `multiprocessing`

Python에서는 `multiprocessing` 모듈을 사용해 여러 프로세스를 만들 수 있다.

```python
from multiprocessing import Process
import os

def work():
    print("자식 프로세스 PID:", os.getpid())

if __name__ == "__main__":
    p = Process(target=work)
    p.start()
    p.join()

    print("부모 프로세스 PID:", os.getpid())
```

### 확인할 것

프로세스가 만들어지면 **각각의 PID**를 확인할 수 있다.

또한 프로세스는 기본적으로 **독립된 메모리 공간**을 사용한다.

```
부모 프로세스
┌──────────────┐
│ 변수 = 10    │
└──────────────┘

        ↓ 독립된 메모리

자식 프로세스
┌──────────────┐
│ 변수 = 10    │
└──────────────┘
```

자식 프로세스에서 변수를 변경해도 부모 프로세스의 변수에 직접 영향을 주지 않는다.

## 2. 멀티스레드 — `threading`

Python에서는 `threading` 모듈을 사용해 여러 스레드를 만들 수 있다.

```python
import threading

def work():
    print("스레드 실행")

t1 = threading.Thread(target=work)
t2 = threading.Thread(target=work)

t1.start()
t2.start()

t1.join()
t2.join()
```

같은 프로세스 안에서 생성된 스레드들은 **코드·데이터·힙 등의 자원을 공유**한다.

따라서 여러 스레드가 같은 변수를 변경할 경우 **동기화 문제**가 발생할 수 있다.

# 🔗 전체 흐름 정리

```
프로세스
  ↓
실행되는 동안 여러 상태를 가짐
  ↓
생성 → 준비 → 실행 → 대기 → 실행 → 종료
                    ↓
             CPU 사용 시간 종료
                    ↓
                  준비

프로세스는 부모-자식 관계를 만들 수 있음
  ↓
프로세스 계층 구조

하나의 프로세스 안에는 여러 실행 흐름이 존재할 수 있음
  ↓
스레드
  ↓
같은 프로세스의 코드·데이터·힙 공유
  ↓
멀티스레드
  ↓
공유 자원 → 빠른 협력 가능
         → 동기화 문제 주의
```

## ⭐ 핵심 정리

> **프로세스 = 실행 중인 프로그램**

> **프로세스 상태 = 생성 → 준비 → 실행 → 대기 → 종료**

> **프로세스 계층 구조 = 부모 프로세스와 자식 프로세스의 트리 구조**

> **`fork()` = 자식 프로세스 생성**

> **`exec()` = 실행할 프로그램 교체**

> **스레드 = 프로세스 내부의 실행 흐름**

> **같은 프로세스의 스레드 = 코드·데이터·힙 공유 + 스택·레지스터는 각자 사용**

> **멀티스레드의 핵심 장점 = 자원 공유가 쉬움**

> **멀티스레드의 핵심 주의점 = 공유 자원에 대한 동기화**
