# [ 11 - 1 CPU 스케줄링 개요 ]

## 1. CPU 스케줄링이란?

앞에서 프로세스는 **준비 상태에서 CPU를 기다린다**고 배웠다.

그렇다면 CPU를 여러 프로세스 중 **누구에게, 언제, 얼마나 할당할까?**

→ 운영체제가 결정하는데, 이것을 **CPU 스케줄링(CPU Scheduling)**&#xC774;라고 한다.

> **CPU 스케줄링 = 운영체제가 프로세스에 CPU를 할당하는 방법을 결정하는 것**

CPU는 한정된 자원이기 때문에 모든 프로세스가 원하는 만큼 사용할 수 없다.
따라서 운영체제는 프로세스의 특성과 우선순위 등을 고려하여 CPU를 배분한다.

---

## 2. 프로세스의 우선순위

모든 프로세스가 CPU를 똑같이 사용하는 것은 아니다.

프로세스마다 CPU를 사용하는 방식이 다르기 때문이다.

* **CPU burst가 긴 프로세스** → CPU 연산을 많이 수행
* **I/O burst가 많은 프로세스** → CPU를 사용하다가 입출력을 기다리는 일이 많음

따라서 운영체제는 프로세스의 **우선순위(Priority)** 등을 고려하여 CPU를 할당한다.

> 어떤 프로세스를 먼저 처리할지는 **CPU 스케줄링의 중요한 기준**이다.

---

## 3. 스케줄링 큐

CPU를 사용하고 싶은 프로세스가 하나뿐이라면 고민할 필요가 없다.

하지만 수많은 프로세스가 CPU나 입출력장치를 기다리고 있다면 **줄을 세워 관리**해야 한다.

이때 사용하는 것이 **스케줄링 큐(Scheduling Queue)**&#xB2E4;.

| 큐                       | 의미                               |
| ----------------------- | -------------------------------- |
| **준비 큐(Ready Queue)**   | CPU를 사용하기 위해 기다리는 프로세스들이 대기      |
| **대기 큐(Waiting Queue)** | 입출력장치 등의 작업이 끝나기를 기다리는 프로세스들이 대기 |

```
프로세스
   ↓
[준비 큐]
   ↓
CPU 할당
   ↓
[실행]
   ↓
 ┌───────────────┐
 ↓               ↓
I/O 요청       실행 완료
 ↓               ↓
[대기 큐]       종료
 ↓
I/O 완료
 ↓
[준비 큐]
```

즉, **프로세스 상태가 바뀌면 기다리는 큐도 달라질 수 있다.**

# 4. 선점형 vs 비선점형 스케줄링

CPU를 사용 중인 프로세스에게서 **CPU를 강제로 빼앗을 수 있는가?**

이것을 기준으로 CPU 스케줄링을 크게 두 가지로 나눌 수 있다.

| 구분        | 선점형                          | 비선점형                                 |
| --------- | ---------------------------- | ------------------------------------ |
| CPU 강제 회수 | **가능**                       | **불가능**                              |
| 특징        | 다른 프로세스에게 CPU를 빠르게 넘길 수 있음   | 한 프로세스가 CPU를 계속 사용                   |
| 장점        | 응답성이 좋고 특정 프로세스의 독점을 막을 수 있음 | 문맥 교환 등의 오버헤드가 상대적으로 적음              |
| 단점        | 문맥 교환 등 오버헤드 발생 가능           | 한 프로세스가 오래 실행되면 다른 프로세스가 오래 기다릴 수 있음 |

### 선점형

현재 CPU를 사용 중인 프로세스에게서 **CPU를 빼앗아 다른 프로세스에게 할당할 수 있는 방식**이다.

예를 들어 A가 CPU를 사용하고 있는데 더 높은 우선순위의 B가 실행되어야 한다면 A의 실행을 중단하고 B에게 CPU를 줄 수 있다.

> 현대 운영체제에서 주로 사용되는 방식이다.

### 비선점형

한 프로세스가 CPU를 할당받으면 **프로세스가 스스로 CPU를 내놓을 때까지** 강제로 빼앗지 않는 방식이다.

프로세스가 실행을 끝내거나 대기 상태로 들어가야 다른 프로세스가 CPU를 사용할 수 있다.

## 🔗 핵심 흐름

```
여러 프로세스가 존재
      ↓
CPU는 한정된 자원
      ↓
누구에게 CPU를 줄 것인가?
      ↓
CPU 스케줄링
      ↓
우선순위 등을 고려
      ↓
준비 큐에서 프로세스 선택
      ↓
CPU 할당
      ↓
실행
      ↓
CPU 사용 종료 / I/O 요청 / 선점
      ↓
다시 준비 큐 또는 대기 큐
```

## ⭐ 핵심 정리

> **CPU 스케줄링 = 운영체제가 CPU를 어떤 프로세스에게 할당할지 결정하는 것**

> **스케줄링 큐 = CPU나 입출력장치를 기다리는 프로세스를 줄 세워 관리하는 것**

> **선점형 = CPU를 강제로 빼앗을 수 있음**

> **비선점형 = CPU를 강제로 빼앗을 수 없음**

> **CPU 스케줄링의 핵심 목적 = CPU를 효율적으로 사용하면서 프로세스들이 적절한 시간 안에 실행되도록 하는 것**
