# 07. 보조기억장치

---

# 07-1. 다양한 보조기억장치

## 📌 학습 목표

* 하드 디스크(HDD)의 주요 물리적 구성 요소와 동작 원리를 이해한다.
* 하드 디스크의 데이터 접근 시간을 이해한다.
* 플래시 메모리(NAND)의 저장 구조와 동작 원리를 이해한다.
* SLC, MLC, TLC, QLC의 차이를 이해한다.
* 페이지와 블록의 차이를 이해한다.
* 가비지 컬렉션이 필요한 이유를 이해한다.

---

# 1. 하드 디스크(HDD)는 데이터를 어떻게 저장하고 위치를 찾아갈까?

하드 디스크(HDD)는 **자기적인 방식으로 데이터를 저장하는 보조기억장치**이다.

HDD는 내부의 원판을 회전시키면서 헤드가 원하는 위치로 이동하여 데이터를 읽고 쓴다.

```
HDD
 │
 ├── 플래터 → 데이터를 저장하는 원판
 ├── 스핀들 → 플래터를 회전시킴
 ├── 헤드 → 데이터를 읽고 씀
 ├── 디스크 암 → 헤드를 이동시킴
 ├── 트랙 → 플래터의 동심원 형태 저장 영역
 ├── 섹터 → 트랙을 나눈 저장 단위
 └── 실린더 → 여러 플래터에서 같은 위치의 트랙을 연결한 영역
```

---

# 2. 플래터(Platter)

**플래터(Platter)**는

> **데이터가 자기적인 방식으로 저장되는 원판**

이다.

HDD 내부에는 하나 이상의 플래터가 들어갈 수 있으며, 플래터가 회전하면서 원하는 데이터가 헤드 아래로 이동한다.

---

# 3. 스핀들(Spindle)

**스핀들(Spindle)**은 플래터를 회전시키는 장치이다.

스핀들에 연결된 모터가 플래터를 빠르게 회전시킨다.

플래터의 회전 속도는 **RPM(Revolutions Per Minute)**으로 나타낸다.

> **RPM = 1분 동안 플래터가 회전하는 횟수**

예를 들어 7,200 RPM이라면 플래터가 1분에 7,200번 회전한다.

---

# 4. 헤드(Head)와 디스크 암(Disk Arm)

**헤드(Head)**는 플래터의 데이터를 읽고 쓰는 장치이다.

헤드는 플래터 표면에 직접 닿지 않고 매우 가까운 위치에서 데이터를 읽고 쓴다.

**디스크 암(Disk Arm)**은 헤드를 원하는 트랙 위치로 이동시키는 역할을 한다.

```
디스크 암
    │
    └── 헤드
          ↓
      플래터
```

즉,

> **디스크 암이 헤드를 이동시키고, 헤드가 실제로 데이터를 읽고 쓴다.**

---

# 5. 트랙(Track)과 섹터(Sector)

플래터의 표면에는 **트랙(Track)**이라는 동심원 형태의 데이터 저장 영역이 존재한다.

``` 
        ┌───────────┐
        │  트랙      │
        │ ┌───────┐ │
        │ │ 트랙   │ │
        │ │ ┌───┐ │ │
        │ │ │   │ │ │
        │ │ └───┘ │ │
        │ └───────┘ │
        └───────────┘
```

그리고 하나의 트랙은 여러 개의 **섹터(Sector)**로 나뉜다.

섹터는 HDD에서 데이터를 저장하고 관리하는 기본적인 단위 중 하나이다.

``
트랙
 ├── 섹터
 ├── 섹터
 ├── 섹터
 ├── 섹터
 └── ...
```

---

# 6. 실린더(Cylinder)

HDD에 플래터가 여러 장 들어 있는 경우, 각각의 플래터에는 트랙이 존재한다.

이때 여러 플래터에서 **같은 위치에 있는 트랙들을 수직으로 연결한 개념**을 실린더(Cylinder)라고 한다.

``` 
플래터 1 → 같은 위치의 트랙
플래터 2 → 같은 위치의 트랙
플래터 3 → 같은 위치의 트랙
             ↓
          하나의 실린더
```

실린더라는 개념을 이용하면 여러 플래터에 걸쳐 데이터를 관리할 수 있다.

---

# 7. HDD의 데이터 접근 시간

HDD에서 원하는 데이터를 읽기 위해서는 단순히 데이터를 찾는 것뿐만 아니라 여러 단계가 필요하다.

대표적인 접근 시간은 다음과 같이 생각할 수 있다.

``` 
접근 시간
= 탐색 시간 + 회전 지연 + 전송 시간
```

---

## ① 탐색 시간(Seek Time)

**탐색 시간**은

> **헤드를 원하는 트랙까지 이동시키는 데 걸리는 시간**

이다.

``` 
현재 위치
   ↓
헤드 이동
   ↓
원하는 트랙 도착
```

헤드가 이동해야 하는 거리가 멀수록 일반적으로 더 많은 시간이 필요하다.

---

## ② 회전 지연(Rotational Latency)

헤드가 원하는 트랙에 도착했다고 해서 바로 데이터를 읽을 수 있는 것은 아니다.

원하는 **섹터가 헤드 아래에 올 때까지 플래터가 회전해야 한다.**

이때 걸리는 시간이 **회전 지연**이다.

```
헤드
 ↓
원하는 트랙은 찾음
 ↓
원하는 섹터가 올 때까지
플래터 회전
 ↓
데이터 위치 도착
```

---

## ③ 전송 시간(Transfer Time)

원하는 섹터까지 찾아갔다면 실제로 데이터를 읽거나 써야 한다.

이때 데이터를 실제로 전송하는 데 걸리는 시간이 **전송 시간**이다.

---

## ⭐ HDD 접근 시간 정리

```
CPU가 데이터 요청
       ↓
헤드를 원하는 트랙으로 이동
       ↓
[ 탐색 시간 ]
       ↓
원하는 섹터가 헤드 아래로 이동
       ↓
[ 회전 지연 ]
       ↓
데이터 읽기 / 쓰기
       ↓
[ 전송 시간 ]
```

따라서,

> **HDD의 접근 시간 = 탐색 시간 + 회전 지연 + 전송 시간**

으로 이해할 수 있다.

---

# 8. 플래시 메모리(Flash Memory)

HDD와 달리 플래시 메모리는 **전기적으로 데이터를 저장하는 반도체 기반 저장 장치**이다.

대표적으로 SSD가 플래시 메모리를 사용한다.

```
HDD
→ 자기적인 방식으로 데이터 저장
→ 플래터가 회전
→ 헤드가 이동

SSD
→ 전기적인 방식으로 데이터 저장
→ 반도체 기반
→ 움직이는 물리적 부품이 없음
```

플래시 메모리는 크게 **NAND 플래시**와 **NOR 플래시**로 나눌 수 있다.

현재 SSD와 같은 대용량 저장장치에는 주로 **NAND 플래시**가 사용된다.

---

# 9. NAND 플래시와 NOR 플래시

### NAND 플래시

> **대용량 데이터를 저장하는 데 적합하여 SSD, USB 메모리, 메모리 카드 등에 널리 사용된다.**

### NOR 플래시

> **읽기 특성이 좋고 코드 저장 등에 활용되는 플래시 메모리**

이번 단원에서는 대용량 저장장치에서 주로 사용되는 **NAND 플래시**를 중심으로 살펴본다.

---

# 10. 플래시 메모리의 저장 단위 - 셀(Cell)

플래시 메모리는 **셀(Cell)**에 전하를 저장하여 데이터를 표현한다.

셀 하나에 저장할 수 있는 비트 수에 따라 여러 종류로 나눌 수 있다.

대표적으로

* SLC
* MLC
* TLC
* QLC

가 있다.

---

# 11. SLC (Single-Level Cell)

**SLC = Single-Level Cell**

> **하나의 셀에 1비트를 저장**

한다.

1비트는 0과 1, 총 2개의 상태를 표현할 수 있다.

### 특징

* 속도가 빠르다.
* 내구성이 좋다.
* 수명이 길다.
* 상대적으로 안정적이다.
* 하지만 셀당 저장하는 데이터가 적기 때문에 같은 용량을 만들려면 많은 셀이 필요하다.
* 따라서 가격이 비싸다.

```
SLC
1 Cell
  ↓
1 bit
```

---

# 12. MLC (Multi-Level Cell)

**MLC = Multi-Level Cell**

> **하나의 셀에 2비트를 저장**

한다.

2비트이므로 하나의 셀에서 총 **4개의 상태**를 표현할 수 있다.

```
01
10
11
```

### 특징

* SLC보다 높은 저장 밀도를 제공한다.
* SLC보다 가격이 저렴하다.
* 성능과 내구성은 일반적으로 SLC보다 낮다.
* 셀당 더 많은 데이터를 저장하기 때문에 같은 물리적 공간에서 더 많은 데이터를 저장할 수 있다.

---

# 13. TLC (Triple-Level Cell)

**TLC = Triple-Level Cell**

> **하나의 셀에 3비트를 저장**

한다.

3비트이므로 하나의 셀에서 총 **8개의 상태**를 표현할 수 있다.

``` 
000
001
010
011
100
101
110
111
```

### 특징

* MLC보다 더 높은 저장 밀도를 제공한다.
* 용량 대비 가격이 저렴하다.
* SLC나 MLC보다 일반적으로 내구성과 쓰기 성능이 낮다.
* 현재 소비자용 SSD에서 널리 사용되는 방식이다.

---

# 14. QLC (Quad-Level Cell)

**QLC = Quad-Level Cell**

> **하나의 셀에 4비트를 저장**

한다.

4비트이므로 하나의 셀에서 총 **16개의 상태**를 표현할 수 있다.

### 특징

* 높은 저장 밀도를 제공한다.
* 같은 공간에서 더 많은 데이터를 저장할 수 있다.
* 용량 대비 가격이 저렴하다.
* 일반적으로 SLC, MLC, TLC보다 쓰기 성능과 내구성 측면에서 불리하다.

---

# 15. SLC / MLC / TLC / QLC 비교

| 구분  | 셀당 저장 비트 | 상태 수 | 저장 밀도 | 일반적인 특징                |
| --- | -------: | ---: | ----- | ---------------------- |
| SLC |     1bit |   2개 | 낮음    | 빠르고 내구성이 좋지만 비쌈        |
| MLC |     2bit |   4개 | 높음    | SLC보다 저렴하고 성능/내구성은 낮아짐 |
| TLC |     3bit |   8개 | 더 높음  | 가격과 용량의 균형이 좋음         |
| QLC |     4bit |  16개 | 매우 높음 | 대용량을 저렴하게 만들기 유리       |

### 💡 핵심

> **하나의 셀에 더 많은 비트를 저장할수록 저장 밀도와 용량 측면에서는 유리하지만, 일반적으로 쓰기 성능과 내구성 측면에서는 불리해진다.**

---

# 16. 셀(Cell)이 모여 플래시 메모리가 된다

셀은 플래시 메모리에서 데이터를 저장하는 기본 단위이다.

하지만 실제 SSD는 셀 하나만 사용하는 것이 아니라 수많은 셀이 모여 구성된다.

```
Cell
 ↓
여러 Cell
 ↓
Page
 ↓
Block
 ↓
여러 Block
 ↓
NAND Flash
 ↓
SSD
```

---

# 17. 페이지(Page)와 블록(Block)

플래시 메모리에서는 **읽기/쓰기와 삭제의 단위가 서로 다르다.**

이 부분이 HDD와 비교했을 때 중요한 특징이다.

### 페이지(Page)

> **플래시 메모리에서 읽기와 쓰기가 이루어지는 기본 단위**

### 블록(Block)

> **여러 페이지가 모여 만들어지며, 삭제(Erase)의 기본 단위**

즉,

``` 
Block
│
├── Page
├── Page
├── Page
├── Page
└── ...
```

**블록 > 페이지**

관계라고 이해하면 된다.

---

# 18. 페이지의 상태

NAND 플래시의 페이지는 데이터를 저장하는 상태에 따라 다음과 같이 생각할 수 있다.

### Free

> **아무 데이터도 저장되어 있지 않아 새로운 데이터를 저장할 수 있는 상태**

### Valid

> **현재 유효한 데이터가 저장되어 있는 상태**

### Invalid

> **더 이상 유효하지 않은 데이터가 저장되어 있는 상태**

Invalid 상태의 데이터는 더 이상 사용하지 않는 데이터이지만, 페이지 자체가 바로 비워지는 것은 아니다.

---

# 19. 플래시 메모리는 덮어쓰기가 불가능하다

플래시 메모리의 중요한 특징 중 하나는

> **기존 데이터를 HDD처럼 바로 덮어쓸 수 없다는 것**

이다.

예를 들어,

``` 
Page A
기존 데이터: A
상태: Valid
```

여기에 새로운 데이터 B를 바로 덮어쓰는 것이 아니라,

```
기존 Page A
A → Invalid

새로운 Page
B → Valid
```

와 같이 새로운 위치에 데이터를 기록한다.

즉,

> **기존 데이터를 바로 수정하는 대신 기존 페이지를 Invalid로 만들고 새로운 페이지에 데이터를 기록한다.**

---

# 20. 그렇다면 Invalid 페이지가 계속 쌓이면?

계속 데이터를 쓰다 보면 Invalid 상태의 페이지가 점점 늘어난다.

``` 
Block

Page 1 → Valid
Page 2 → Invalid
Page 3 → Valid
Page 4 → Invalid
Page 5 → Invalid
```

이렇게 되면 실제로 사용할 수 있는 빈 공간이 부족해진다.

그렇다면 Invalid 페이지를 정리해서 다시 사용할 수 있는 공간을 만들어야 한다.

이때 등장하는 것이 **가비지 컬렉션(Garbage Collection)**이다.

---

# 21. 가비지 컬렉션(Garbage Collection)

가비지 컬렉션은

> **유효한 데이터는 다른 블록으로 옮기고, 기존 블록을 삭제하여 새로운 데이터를 저장할 수 있는 공간을 확보하는 작업**

이다.

예를 들어,

```
기존 Block

Page 1 → Valid
Page 2 → Invalid
Page 3 → Valid
Page 4 → Invalid
```

여기에서 유효한 데이터만 새로운 블록으로 복사한다.

``` 
새로운 Block

Page 1 → Valid
Page 2 → Valid
```

그 다음 기존 블록 전체를 삭제하여 새로운 데이터를 저장할 수 있는 공간으로 만든다.

```
기존 Block
    ↓
전체 Erase
    ↓
빈 Block
```

---

# 22. 가비지 컬렉션의 전체 과정

```
① 데이터가 계속 기록됨
        ↓
② 기존 데이터가 Invalid 상태가 됨
        ↓
③ Invalid 페이지가 쌓임
        ↓
④ 새로운 데이터를 저장할 공간 부족
        ↓
⑤ Valid 데이터만 새로운 블록으로 이동
        ↓
⑥ 기존 블록 전체 삭제
        ↓
⑦ 새로운 데이터를 저장할 빈 공간 확보
```

### 💡 핵심

> **플래시 메모리는 덮어쓰기가 불가능하기 때문에 Invalid 페이지가 발생하고, 이를 정리하여 공간을 확보하기 위해 가비지 컬렉션이 필요하다.**

# ⭐ 23. HDD vs SSD 핵심 비교

| 구분      | HDD                  | SSD            |
| ------- | -------------------- | -------------- |
| 저장 방식   | 자기적 방식               | 반도체 방식         |
| 주요 구성   | 플래터, 헤드, 스핀들 등       | NAND 플래시 메모리 등 |
| 움직이는 부품 | 있음                   | 없음             |
| 데이터 접근  | 헤드 이동 + 플래터 회전       | 전기적으로 접근       |
| 대표적인 특징 | 물리적 움직임 때문에 접근 지연 발생 | 빠른 접근 속도       |
| 저장장치    | 자기 디스크               | 플래시 메모리        |

# 07-2. RAID의 정의와 종류

## 📌 학습 목표

* RAID가 무엇인지 이해한다.
* RAID를 사용하는 이유를 이해한다.
* RAID 0, 1, 4, 5, 6의 구조와 특징을 비교한다.
* 성능과 데이터 안전성이 RAID 구성에 따라 어떻게 달라지는지 이해한다.

---

# 1. RAID란?

**RAID = Redundant Array of Independent Disks**

RAID는

> **여러 개의 물리적인 보조기억장치를 하나의 논리적인 저장장치처럼 묶어 사용하는 기술**

이다.

HDD 여러 개를 묶을 수도 있고, SSD 여러 개를 묶어 사용할 수도 있다.

```
Disk 1 ─┐
Disk 2 ─┤
Disk 3 ─┼──→ RAID → 하나의 논리적 저장장치
Disk 4 ─┘
```

---

# 2. 왜 보조기억장치를 RAID로 구성할까?

RAID를 사용하는 대표적인 목적은 크게 두 가지이다.

### ① 성능 향상

여러 디스크에 데이터를 분산하여 저장하고 동시에 읽고 쓸 수 있도록 하면 **입출력 성능을 높일 수 있다.**

### ② 데이터 안전성 확보

일부 RAID 방식은 데이터를 복제하거나 **패리티(Parity)** 정보를 저장한다.

따라서 특정 디스크에 장애가 발생하더라도 데이터를 복구할 수 있다.

> **RAID는 구성 방식에 따라 성능과 데이터 안전성을 다르게 확보한다.**

---

# 3. RAID 0 - 스트라이핑(Striping)

RAID 0은 데이터를 여러 디스크에 **분산해서 저장하는 방식**이다.

```
데이터
 ↓
A B C D
 ↓
┌──────┬──────┬──────┬──────┐
│Disk 1│Disk 2│Disk 3│Disk 4│
│  A   │  B   │  C   │  D   │
└──────┴──────┴──────┴──────┘
```

데이터를 여러 디스크에 나누어 저장하기 때문에 여러 디스크에서 동시에 작업할 수 있다.

### 장점

* 읽기/쓰기 성능 향상
* 여러 디스크를 병렬적으로 활용할 수 있음
* 디스크 용량을 효율적으로 사용할 수 있음

### 단점

* **데이터 안전성이 없다.**
* 디스크 하나라도 고장 나면 해당 디스크에 있던 데이터가 손실된다.
* 분산 저장된 데이터의 일부가 사라지므로 전체 데이터를 복구하기 어렵다.

### 💡 핵심

> **RAID 0 = 속도 중심, 데이터 보호 없음**

---

# 4. RAID 1 - 미러링(Mirroring)

RAID 1은 같은 데이터를 여러 디스크에 **복제해서 저장하는 방식**이다.

```
데이터
  ↓
┌────────┐
│ Disk 1 │ → A B C D
└────────┘

┌────────┐
│ Disk 2 │ → A B C D
└────────┘
```

Disk 1과 Disk 2에 동일한 데이터가 저장된다.

### 장점

* 데이터가 복제되어 있어 디스크 장애에 강하다.
* 한쪽 디스크가 고장 나더라도 다른 디스크의 데이터를 사용할 수 있다.
* 복구가 비교적 간단하다.

### 단점

* 동일한 데이터를 복제해서 저장하기 때문에 **실제 사용 가능한 용량이 줄어든다.**
* 1TB 디스크 2개를 RAID 1로 구성하면 일반적으로 사용할 수 있는 용량은 약 1TB이다.
* 같은 용량을 확보하려면 더 많은 저장장치가 필요하므로 비용이 증가한다.

### 💡 핵심

> **RAID 1 = 데이터 복제, 안전성 중심**

---

# 5. RAID 4

RAID 4는 데이터를 여러 디스크에 **스트라이핑**하고, 데이터 복구를 위한 **패리티(Parity)** 정보를 별도의 디스크에 저장한다.

```
Disk 1    Disk 2    Disk 3    Parity
  A         B         C          P
  D         E         F          P
  G         H         I          P
```

### 패리티란?

패리티는

> **일부 데이터가 손실되었을 때 손실된 데이터를 복구하는 데 사용할 수 있는 추가 정보**

이다.

### 장점

* RAID 0처럼 데이터를 분산하여 저장할 수 있다.
* 패리티 정보를 이용하여 디스크 장애 시 데이터를 복구할 수 있다.

### 단점

패리티를 하나의 디스크에 집중해서 저장하기 때문에 데이터를 쓸 때 패리티 디스크에 작업이 몰릴 수 있다.

이로 인해 **패리티 디스크가 병목 지점**이 될 수 있다.

### 💡 핵심

> **RAID 4 = 데이터는 분산 + 패리티는 하나의 디스크에 집중**

---

# 6. RAID 5

RAID 5는 RAID 4의 문제를 개선한 방식이다.

RAID 4와 마찬가지로 데이터를 스트라이핑하고 패리티 정보를 이용하지만,

> **패리티를 특정 하나의 디스크에 몰아두지 않고 여러 디스크에 분산하여 저장한다.**

```
Disk 1    Disk 2    Disk 3    Disk 4

  A         B         C         P
  D         E         P         F
  G         P         H         I
  P         J         K         L
```

패리티 위치가 여러 디스크에 분산된다.

### 장점

* 데이터를 여러 디스크에 분산하여 저장
* 패리티를 이용하여 데이터 복구 가능
* RAID 4의 전용 패리티 디스크 병목 문제를 완화

### 단점

* 일반적으로 디스크 하나의 장애까지 복구할 수 있다.
* 데이터를 쓸 때 패리티를 계산해야 하기 때문에 RAID 0보다 쓰기 작업이 복잡하다.

### 💡 핵심

> **RAID 5 = 데이터 분산 + 패리티 분산**

---

# 7. RAID 6

RAID 6은 RAID 5와 비슷하지만 **두 종류의 패리티 정보**를 저장한다.

```
Disk 1    Disk 2    Disk 3    Disk 4    Disk 5

  A         B         C        P1        P2
  D         E        P1        F         P2
  G         P1       H         I         P2
```

두 개의 독립적인 패리티 정보를 사용하기 때문에 **동시에 두 개의 디스크가 고장 나더라도 데이터를 복구할 수 있다.**

### 장점

* RAID 5보다 높은 장애 허용 능력
* 디스크 2개가 동시에 고장 나더라도 데이터 복구 가능

### 단점

* 패리티 정보를 두 종류 계산해야 한다.
* RAID 5보다 쓰기 작업에 더 많은 연산이 필요하다.
* 두 개의 디스크 용량을 패리티에 사용하므로 사용 가능한 저장 공간이 더 줄어든다.

### 💡 핵심

> **RAID 6 = 데이터 분산 + 두 개의 패리티 + 최대 2개 디스크 장애 대응**

---

# 8. RAID 0 / 1 / 4 / 5 / 6 비교

| RAID   | 방식                | 성능              | 데이터 보호 | 특징                |
| ------ | ----------------- | --------------- | ------ | ----------------- |
| RAID 0 | 스트라이핑             | 높음              | 없음     | 여러 디스크에 데이터를 분산   |
| RAID 1 | 미러링               | 읽기 성능에 유리할 수 있음 | 높음     | 데이터를 복제해서 저장      |
| RAID 4 | 스트라이핑 + 전용 패리티    | 높음              | 가능     | 패리티 디스크에 병목 발생 가능 |
| RAID 5 | 스트라이핑 + 분산 패리티    | 높음              | 가능     | 패리티를 여러 디스크에 분산   |
| RAID 6 | 스트라이핑 + 이중 분산 패리티 | 상대적으로 낮음        | 매우 높음  | 두 디스크 장애까지 대응 가능  |

---

# 9. RAID의 핵심 개념

RAID를 이해할 때는 크게 세 가지 개념을 기억하면 된다.

### 스트라이핑(Striping)

> **데이터를 여러 디스크에 나누어 저장**

→ 여러 디스크를 동시에 활용하여 성능을 높이는 데 유리

### 미러링(Mirroring)

> **같은 데이터를 여러 디스크에 복제하여 저장**

→ 디스크 장애에 대비하는 데 유리

### 패리티(Parity)

> **데이터가 손실되었을 때 복구할 수 있도록 추가로 저장하는 정보**

→ RAID 4, 5, 6 등에서 사용

# 💡 11. 내가 이해한 핵심 흐름

이번 단원에서는 **보조기억장치가 데이터를 저장하는 방식과 여러 저장장치를 효율적으로 사용하는 방법**을 배웠다.

먼저 HDD는

```
플래터
  ↓
트랙 / 섹터
  ↓
헤드 이동 + 플래터 회전
  ↓
데이터 접근
```

과 같은 물리적인 방식으로 데이터를 읽고 쓴다.

반면 SSD는 NAND 플래시를 사용하며,


셀
 ↓
페이지
 ↓
블록
 ↓
NAND 플래시
 ↓
SSD
```

와 같은 구조를 가진다.

특히 NAND 플래시는 **기존 데이터를 바로 덮어쓸 수 없기 때문에** 기존 페이지를 Invalid 상태로 만들고 새로운 페이지에 데이터를 기록한다.

그 결과 Invalid 페이지가 쌓이면 **가비지 컬렉션**을 통해 유효한 데이터만 새로운 블록으로 옮기고 기존 블록을 삭제하여 공간을 확보한다.

그리고 RAID는 여러 보조기억장치를 하나의 논리적인 저장장치처럼 묶어

> **성능 향상 또는 데이터 안전성 확보**

를 목적으로 사용한다.

# ⭐ 12. 이번 단원 한 문장 정리

> **HDD는 플래터와 헤드를 이용해 자기적으로 데이터를 저장하고, SSD는 NAND 플래시의 셀·페이지·블록 구조를 이용해 데이터를 저장하며, RAID는 여러 보조기억장치를 묶어 저장 성능을 높이거나 데이터 장애에 대비한다.**
